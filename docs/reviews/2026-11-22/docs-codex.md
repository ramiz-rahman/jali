# Jali documentation review

## Verdict

The docs explain Jali’s spatial model well. The live folding and layout-tree demos make the behavior easier to understand than prose alone.
The docs are below the 1.0 bar for integration. Three displayed setup examples throw at startup, and the URL and persistence recipes can produce results the guides promise to avoid.
The reference names the main exports well. Several signatures, option tables, and packaged Markdown examples have drifted.
The docs TypeScript check, all 14 reference tests, and the 33-file packaged Markdown check passed. I also checked 55 inline TypeScript and JSX blocks and reproduced the startup, router, persistence, and Quickstart findings against the source. This was a read-only review. Browser and assistive-technology behavior was assessed from source.

## Target architecture

Keep Astro’s static pages, the live islands, and the installed-version Markdown. The prior review’s whole-site hydration, draft-route, search, and agent-index findings have been addressed in the current source. Keep the deliberate separation of **Learn**, **Guides**, and **Reference**. Give the guides task-oriented entry points, and give high-use APIs such as `createJali`, `JaliRoot`, `definePane`, and `usePaneState` short, individually addressable reference pages. Retain existing anchors as redirects or aliases. This takes the task paths of TanStack Query, the usage and accessibility sections of Radix, and the teaching sequence of react.dev. [Jali’s static-site decision](/Users/ramizrahman/Projects/jali/.claude/worktrees/review-93526af/docs/DECISIONS.md:1093), [TanStack Query](https://tanstack.com/query/latest/docs/framework/react), [Radix Tabs](https://www.radix-ui.com/primitives/docs/components/tabs), [Learn React](https://react.dev/learn)

Use the package exports and TypeScript declarations to generate the mechanical parts of the reference. Keep behavior, tradeoffs, and examples authored. Give each runnable example one source used by the page, Markdown export, and checks. Give shorter excerpts explicit context so readers know which names come from their app. Keep the published UI and behavior intact while making those contracts easier to find and verify.
