# Jali React quality review · `93526af`

## Verdict

The core/React split, fold projection, pane error boundaries, and DOM-only divider drag are worth keeping.  
Three release blockers remain. A stale setter can put one object’s draft into another, a normal selector can crash the tree, and a responsive change can discard a mounted pane’s local state.  
The earlier React 18 hydration fix covers measurement. The default browser bootstrap can still produce different markup from the server.  
`createJali({ label })` already solves the reported cross-workspace landmark naming case. Duplicate pane names and colliding DOM IDs remain.  
Keep Pop out experimental until it preserves pane state and safely owns the floating window’s lifecycle.  
Both TypeScript projects passed with incremental output disabled. I reproduced the failures marked below in memory on React 19. Vitest and Playwright were blocked by sandbox cache writes. React 18, real-browser behavior, and the packed-size gate remain unverified.

## Target architecture

- **One persistent React host per pane ID.** Keep pane content under a stable React parent and portal it into a persistent DOM container. Move that container when the pane enters a scrolling row, Single view, or PiP. Keep object identity separate so data writes remain scoped to the object while expensive views such as MapLibre can reuse a mounted component.
- **One selector implementation over immutable snapshots.** Use cached selectors for React reads and an explicit server bootstrap snapshot. Keep pointer coordinates on their own subscription path. Retain the existing direct-DOM divider preview and single layout commit on release.
- **One committed renderer attachment per workspace.** Attach the DOM port at commit, with cleanup. Give the surface, modal layer, live region, and optional PiP document an explicit owner. Use that ownership for focus, input, direction, and theme. Keep the low-specificity `jali` layer and the existing appearance.
