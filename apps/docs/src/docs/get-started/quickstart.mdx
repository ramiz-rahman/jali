This page builds a small app, one file at a time: a note with a button that opens the next note beside it. The finished app is [`examples/minimal`](https://github.com/ramiz-rahman/jali/tree/master/examples/minimal) in the repo, which adds a launcher and makes the panes the page's `<main>`.

You need Node and a React app. Start from a new one, or skip this step and use your own:

```sh
npm create vite@latest notes -- --template react-ts
cd notes
```

<Steps>
<Step title="Install Jali">

<Install packages="jali" />

One package: `jali` holds the model (the layout, the panes and their commands) and has no framework; `jali/react` renders it. If your app links Jali from a checkout or a monorepo, see [Installation](/get-started/installation#linked-or-in-a-monorepo).

</Step>
<Step title="Define a pane">

A [pane kind](/get-started/key-concepts#kind) says what one kind of pane shows and how. This one shows a note.

<Code code={note} filename="note.tsx" />

- `"note"` is the kind's name. Every pane of this kind carries it.
- `params` says what a note pane needs to know: its `id`, a number. A link turns every value into text, so `Number` reads it back as a number.
- `title` names the pane in its header, its tab and ⌘K.
- `Component` renders the pane. It gets the params, typed, along with the functions a pane uses to open other panes.

`note` is now also how you name a note: `note({ id: 1 })` is the [ref](/get-started/key-concepts#ref) of note 1, `{ kind: "note", params: { id: 1 } }`. You use refs to open panes and to write layouts.

</Step>
<Step title="Create the instance">

`createJali` makes the [instance](/get-started/key-concepts#instance): it holds the panes, focus, history and settings. It takes the kinds it can show and the [layout](/get-started/key-concepts#layout-tree) it opens on.

<Code code={jaliCode} filename="jali.ts" />

The layout here is one pane, note 1. Several are written the same way: `row(note({ id: 1 }), note({ id: 2 }))` puts panes side by side, and `column(...)` one above the other. See [Lay out panes](/guides/layouts).

`features` turns on what Jali does beyond laying out panes. `defaultFeatures()` is Jali's usual set: the layout in the address bar, the ⌘K palette, Settings and the chooser. Reload the page and the layout comes back; Back and Forward step through changes. If the address already holds a layout, that one opens instead. An app that wants less picks each feature from its own entry, and ships only those: see [Features](/reference/features).

</Step>
<Step title="Render it">

`<JaliRoot>` draws the panes and the features' dialogs, such as the ⌘K palette. While it is on the page, it also turns on the keyboard, Back and Forward, the theme and saving.

<Code code={main} filename="main.tsx" />

The panes fill the box you give them, so that box needs a height: here `html`, `body` and `#root` are the full window. To add your own top bar or sidebar, put it inside `<JaliRoot>` with `<JaliView />` where the panes go: the panes take the room it leaves. If the box has no height, the panes have none either, and a warning in the console says so while you develop.

Screen readers meet the panes as a region named "Panes", inside your page's own `<main>`. When Jali is the whole page and it has no `<main>` of its own, pass `landmark: "main"` to `createJali` so the panes are the page's `<main>`.

</Step>
<Step title="Add the styles and the layer line">

`jali/styles.css` is Jali's default theme and the panes' layout. Every rule in it sits in a CSS cascade layer named `jali`.

<Code code={css} lang="css" filename="app.css" highlight="2" />

The `@layer` line names the order of the layers once. Your resets go in a layer before `jali`; your own styles go after it, or outside any layer, and win without `!important`. With Tailwind, the line is `@layer theme, base, jali, components, utilities;`.

Run the app. You see note 1, filling the window. Press ⌘K (Ctrl+K on Windows and Linux) to see every command.

</Step>
<Step title="Open a pane beside">

A pane opens another with `openBeside`. Pass it the ref of what to open.

<Code code={openBeside} filename="note.tsx" highlight="7,10-12" />

Click the button in note 1. Note 2 opens to its right, and focus stays in note 1, so you can keep working where you were. Drag the line between them to resize.

Click note 1's button again. Note 2 is already beside it, so Jali opens no copy: it lights note 2 up for a moment and says "Already open". A link never opens a second copy of a pane it opened.

Keep clicking the button in the newest note. Each click opens the next note beside the one you clicked in. When the panes no longer fit at their minimum width, some fold into tabs, and the note you are working in stays on screen. Widen the window and they come back. [How a layout fits](/learn/fitting) explains the order, and [Opening and linking](/learn/opening-and-linking) explains what `openBeside` does when a pane opens several links.

</Step>
</Steps>
