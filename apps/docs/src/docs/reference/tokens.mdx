Jali's styles read only `--jali-*` custom properties, called tokens. To retheme, set any of them on `:root` or on part of the page. The derived tokens follow the accent.

```css
/* The whole page */
:root { --jali-accent: #0f766e; }

/* One instance: an element around its <JaliRoot> */
.orders { --jali-radius: 0.25rem; }
```

**Where to set them.** Apart from the few read in place (each says so below), Jali declares each token once, on its root, inside `:where()`. So your own declaration wins at any specificity and in any import order, even with a theme scope in between. Set it:

- on `:root`, for the whole page;
- on any element around Jali's root, for one instance;
- or on the root itself, `[data-jali]`.

Jali's theme sits in the `jali` layer, so set tokens outside any layer, or in a layer after `jali`.

**Light and dark.** Jali's defaults are `light-dark()` pairs, and the `color-scheme` where they are used picks one:

- dark under `prefers-color-scheme: dark`, and inside a `.dark` or `[data-theme="dark"]` scope;
- light inside a `.light` or `[data-theme="light"]` scope.

A started instance sets `data-theme` on `<html>` from its theme setting, unless it was made with `pageTheme: false`.

**Leave `--jali-default-*` alone.** Names starting `--jali-default-` are the theme's internal palette: don't set or read them.

## Panes

A pane's edge and shadow, at rest and focused. These are read in place: Jali doesn't declare them on the root, its pane styles read each with its default (`var(--jali-pane-border, var(--jali-border))`), so a default that names another token follows that token wherever you set it. Set them like any other token, once, and the focused pane, a maximised one and a drag all follow, with no rule for `[data-focused]` of your own:

```css
.jali-pane {
  --jali-pane-border: transparent;
  --jali-pane-shadow: 0 1px 2px rgb(0 0 0 / 0.12);
  --jali-pane-shadow-focused: 0 0 0 2px var(--jali-accent), 0 1px 2px rgb(0 0 0 / 0.12);
}
```

## Spacing

Written by Jali, not set by you. The layout measures in pixels, so the space between panes is an option, `createJali({ gap })`, and `<JaliRoot>` writes it on its root and its layer as these two variables. Read them in your own styles to line things up with the panes; setting them in CSS moves nothing.

| Token | What it is | Default |
|---|---|---|
| `--jali-gap` | The space between panes, and the gutter a strip's scrollbar sits in (`createJali({ gap })`). | `6px` |
| `--jali-inset` | The space between the edges of Jali's root and its panes (always the same as the gap). | the gap |

## Derived

Mixed from `--jali-accent` on `:root` and again on every Jali root (`[data-jali]`) and dialog (`.jali-scrim`), so an accent set on a subtree gets matching tints there. Set one yourself to override the mix.

## The Tailwind bridge

`jali/tailwind.css` points Jali's tokens at your Tailwind theme's variables, the same names Chakni reads. Import it after Jali's styles, in the stylesheet Tailwind builds, and declare the layer order so your utilities win:

```css
@layer theme, base, jali, components, utilities;
@import "tailwindcss";
@import "jali/styles.css";
@import "jali/tailwind.css";
```

Each token reads the first of your variables that is defined, else Jali's own default for the current theme. Your variables switch with your dark mode, so Jali follows. Tailwind drops theme variables that nothing uses; this file uses them, so keep it in the build Tailwind processes (or mark the theme `@theme static`). Tokens not listed keep Jali's values.
