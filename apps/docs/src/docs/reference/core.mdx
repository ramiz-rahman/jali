The framework-free part of Jali: the workspace, the layouts it shows, the address and storage ports, commands and keys. Render it with [@jali/react](/reference/react). Types have their own page, [@jali/core types](/reference/core/types); the pure layout operations are on [The layout namespace](/reference/core/layout).

```sh
npm install @jali/core
```

Framework adapters import `@jali/core/adapter`, which exports everything inside the package. Apps need only what is on this page.

## The workspace

<Entry name="createJali" kind="function" from="@jali/core" signature={`createJali(options: JaliOptions): Jali`} example={createCode} exampleFile="workspace.ts">

Makes one workspace, ready to render: its state, the model derived from it, its actions and its keymap. Each workspace has its own; nothing is shared between two on one page.

Before it returns, it reads the address (a layout link opens as it is, a curated page link opens the page, a link that can't be read opens the starting layout with an error toast), adds what is on screen to Recent, fits the layout to the room and focuses the first pane. A page-only app (a `page` with no `layout` and no `presets`) starts with its page open on `firstItem`, and "Open Workspace" is refused. It throws ``Jali: give the workspace a `layout`, `presets` or a `page` to start from`` when it has none of them.

Its listeners (keys, Back and Forward, theme and saving) start with `jali.start()`, which `<JaliRoot>` calls while it is mounted.

<Entry name="actions" kind="namespace" from="@jali/core (jali.actions)" note="A member of the workspace, not an import" signature={`jali.actions.openBeside(pane: PaneTarget, ref: ObjectRef): ActionResult`} example={readCode} exampleFile="actions.ts">

What an app asks the workspace to do. Each action reads the current state, makes its change once (layout, focus, address, announcement, toast) and returns what happened: `{ ok: true, pane }`, or `{ ok: false, reason }` with the reason it did not.

The pane comes first, by its id or by the object it shows: `close("order")` and `close(orderKind({ id: 7 }))` both work. An action that would remove or replace a pane with unsaved work is held instead (`reason: "unsaved"`), and "Discard unsaved changes?" opens. A following detail with unsaved work keeps its object and says so, while the list's other followers move on. Every action is listed under <Ref to="JaliActions" page="/reference/core/types" />.

</Entry>

## Pane params

What a kind's refs hold, in its `params`: `Number`, `String`, `Boolean`, `oneOf(...)` or your own function, each required unless wrapped in `optional`. The [Pane kinds guide](/guides/pane-kinds#params) explains what happens to a ref that is missing a required param. Both are also exported from `@jali/react`.

<Entry name="optional" kind="function" from="@jali/core, @jali/react" signature={`optional<T extends ParamType>(type: T): OptionalParam<T>`} example={paramsCode} exampleFile="ticket.tsx">

A param a ref may leave out. The kind's code sees it as optional (`tab?: string`), and its ref maker takes it or not. An optional param given as `undefined` is left out of the ref, as a link would leave it.

<Params>
<Param name="type" type="ParamType" required>How to read it when it is there: `Number`, `String`, `Boolean`, `oneOf(...)` or a function.</Param>
</Params>

<Returns type="OptionalParam<T>" />

</Entry>

<Entry name="oneOf" kind="function" from="@jali/core, @jali/react" signature={`oneOf<const V extends readonly (string | number)[]>(...values: V): OneOf<V[number]>`} compact>

A param that is one of a few values: `oneOf("open", "closed")` gives `"open" | "closed"`. Values are compared as text, so `oneOf(10, 25)` reads `"25"` from a link as `25`. Any other value can't be read, and the ref doesn't open.

<Params>
<Param name="values" type="(string | number)[]" required>The values it can be.</Param>
</Params>

<Returns type="OneOf<V[number]>">A reader, with the values as `values`.</Returns>

</Entry>

## Layouts

<Entry name="row" kind="function" from="@jali/core" signature={`row(options?: SizeOptions, ...children: (Draft | ObjectRef)[]): Draft`} example={builderCode} exampleFile="layouts.ts">

Children side by side. A child is a ref (a pane showing it), a `pane(ref, options)`, or another `row`, `column` or `tabs`. Options come first when there are any: `row({ weight: 2 }, a, b)`.

Nodes without an `id` are named after what they hold: `"row"`, `"column"`, `"tabs"`, or the pane's kind, then `"order-2"` and so on. Give an `id` to a pane another one links to, or that your code names.

<Params>
<Param name="options" type="SizeOptions">`id`; `weight` (its share of the parent, default 1) or `px` (a fixed length).</Param>
<Param name="children" type="(Draft | ObjectRef)[]" required />
</Params>

<Returns type="Draft">For `createJali({ layout })`, a preset's `layout`, or <Ref to="toLayout" />.</Returns>

</Entry>

<Entry name="column" kind="function" from="@jali/core" signature={`column(options?: SizeOptions, ...children: (Draft | ObjectRef)[]): Draft`} compact>

Children one above the other. Otherwise the same as <Ref to="row" />.

</Entry>

<Entry name="tabs" kind="function" from="@jali/core" signature={`tabs(options?: TabsOptions, ...panes: (PaneDraft | ObjectRef)[]): Draft`} compact>

Panes as tabs in one place: a stack the person made. `options.active` names the tab shown (default: the first); `id`, `weight` and `px` as for <Ref to="row" />.

</Entry>

<Entry name="pane" kind="function" from="@jali/core" signature={`pane(ref: ObjectRef, options?: PaneNodeOptions): PaneDraft`} compact>

<Param name="options" type="PaneNodeOptions">

<ChildParams label="options">

<Param name="weight" type="number" default="1">Its share of the parent.</Param>
<Param name="px" type="number">A fixed length along the parent's axis instead.</Param>

<Param name="priority" type={`"primary" | "supporting"`}>Supporting panes give way first when room runs out.</Param>

<Entry name="DEFAULT_KEYMAP" kind="constant" from="@jali/core" signature={`const DEFAULT_KEYMAP: { readonly "palette.toggle": readonly ["Mod+K"]; … }`} example={keymapCode} exampleFile="keymap.ts" exampleHighlight="8">

The default bindings: command id to one or more binding strings. `Mod` is ⌘ on a Mac and Ctrl elsewhere. Each id and its keys, printed for both platforms, are on the [Commands](/reference/commands) page.

The defaults keep to three rules:

- single character keys belong to the focused content;
- no keys the browser keeps for itself (⌘W, ⌘T, Ctrl+Tab and the like), no Ctrl+Alt, and no ⌘ or Ctrl with a digit;
- one prefix, ⌘K or Ctrl+K, which opens the palette and starts a two-step chord whose second step keeps Mod held.

</Entry>

## Words

<Entry name="en" kind="constant" from="@jali/core" signature={`const en: Messages`} example={messagesCode} exampleFile="messages.ts">

Jali's English messages: every word it shows or says, by area (`announcements`, `toasts`, `commands`, `commandGroups`, `keys`, `palette`, `chooser`, `confirmDiscard`, `settings`, `tabs`, `shelf`, `pane`, `peek`, `workspace`, `page`, `drop`). ## Lists and their detail

<Entry name="activeItemPort" kind="function" from="@jali/core" signature={`activeItemPort(jali: Jali, pane: NodeId, mapping: ActiveItemMapping): ActiveItemPort`} example={activeCode} exampleFile="active-item.ts">

Lets a list inside a pane keep its current item through the workspace, so the pane's following detail follows it, Space shows it and an open peek steps with it. The shape matches Chakni's Quick Look port, so a Chakni collection plugs in with no dependency either way. In React, `useActiveItemPort`.

`write(id, "step")` reports the selection (the detail follows once it rests, 150 ms). `"open"` also shows the item: in the following detail when it is on screen, else the peek sheet. `"close"` closes the peek only if this pane opened it; the selection stays. `itemId` reads the pane's selection through `idOf`.

## Geometry

<Entry name="GAP" kind="constant" from="@jali/core" signature={`const GAP: number`} compact>

The gap between panes and the workspace's inset, in pixels (6). For measuring a workspace from outside: its usable area is its element's size minus `GAP * 2`.

## The layout namespace

<Entry name="layout" kind="namespace" from="@jali/core" signature={`import { layout } from "@jali/core";`} example={layoutCode} exampleFile="layout.ts">

The pure layout tree API: every operation takes a layout (and usually the view and a `LayoutContext`) and returns a new one; nothing is changed in place. The workspace's actions are built on it.
