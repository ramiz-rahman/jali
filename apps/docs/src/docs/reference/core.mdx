The framework-free part of Jali: the instance, the layouts it shows, the address and storage ports, commands and keys. Render it with [jali/react](/reference/react). Types have their own page, [jali types](/reference/core/types).

```sh
npm install jali
```

Framework adapters import `jali/adapter`: everything on this page, and, by name, what an adapter needs from inside the package, such as the `DomPort` through which the core finds the adapter's elements, the instance's store (`storeOf`), and the pure layout operations (`layout`). Apps need only what is on this page.

## The instance

<Entry name="createJali" kind="function" from="jali" signature={`createJali(options: JaliOptions): Jali<RefOf<kinds>, PageOf<page>>`} example={createCode} exampleFile="jali.ts">

Makes one instance, ready to render: its state, the model derived from it, its actions and its keymap. Each instance has its own; nothing is shared between two on one page.

Before it returns, it reads the address (a layout link opens as it is, a curated page link opens the page, a link that can't be read opens the starting layout with an error toast), adds what is on screen to Recent, fits the layout to the room and focuses the first pane. A page-only app (a `page` with no `layout` and no `presets`) starts with its page open on `firstItem`, and leaving it is refused. It throws `Jali: no layout to start from can be shown` when it has none of them, or when none of them can be shown (a kind it doesn't have, a param it can't read), with the first reason after a colon.

Its type comes from what it is given: `jali.actions` takes refs of these kinds only, events and the model say which kind (`ref.kind` narrows `ref.params`), and `jali.page` is there only with a `page`. Declare it once as `Register` and the React hooks are typed by it too.

Its listeners (keys, Back and Forward, theme and saving) start with `jali.start()`, which returns their stop and can start again; `<JaliRoot>` starts it while mounted and stops it on unmount. `jali.destroy()` is the end.

<Entry name="actions" kind="namespace" from="jali (jali.actions)" note="A member of the instance, not an import" signature={`jali.actions.openBeside(pane: PaneTarget, ref: ObjectRef, options?: OpenBesideOptions): ActionResult`} example={readCode} exampleFile="actions.ts">

What an app asks the instance to do with panes and layouts; a curated page's actions are `jali.page` (<Ref to="JaliPage" page="/reference/core/types" />) and the dialogs' `jali.dialogs` (<Ref to="JaliDialogs" page="/reference/core/types" />). Each action reads the current state, makes its change once (layout, focus, address, announcement, toast) and returns what happened: `{ ok: true, pane }`, or `{ ok: false, reason }` with the reason it did not.

The pane comes first, by its id or by the object it shows: `close("order")` and `close(orderKind({ id: 7 }))` both work. An action that would remove or replace a pane with unsaved work is held instead (`reason: "unsaved"`), and "Discard unsaved changes?" opens. A following detail with unsaved work keeps its object and says so, while the list's other followers move on. Every action is listed under <Ref to="JaliActions" page="/reference/core/types" />.

</Entry>

## Pane params

What a kind's refs hold, in its `params`: `Number`, `String`, `Boolean`, `oneOf(...)` or your own function, each required unless wrapped in `optional` or `appOnly`. The [Pane kinds guide](/guides/pane-kinds#params) explains what happens to a ref that is missing a required param. 

<Entry name="optional" kind="function" from="jali" signature={`optional<T extends ParamType>(type: T, options?: ParamOptions): OptionalParam<T>`} example={paramsCode} exampleFile="ticket.tsx">

A param a ref may leave out. The kind's code sees it as optional (`tab?: string`), and its ref maker takes it or not. An optional param given as `undefined` is left out of the ref, as a link would leave it.

<Params>
<Param name="type" type="ParamType" required>How to read it when it is there: `Number`, `String`, `Boolean`, `oneOf(...)` or a function.</Param>
<Param name="options.link" type="false">The param is the pane's own state for this page load, and stays out of the address: `runId: optional(String, { link: false })`. Jali leaves it out of every link it writes (the address bar, Copy link, Back and Forward). Unlike `appOnly`, it is part of what the pane shows (`chart({ runId: "a" })` and `chart({ runId: "b" })` are two objects), and a link that does carry it still sets it. Back and Forward keep it on a pane that is still open; after a reload the pane has none, unless the preset the address names gave it one. Use it for a value that means nothing in another tab: a run id, a key into memory.</Param>
</Params>

<Returns type="OptionalParam<T>" />

</Entry>

<Entry name="appOnly" kind="function" from="jali" signature={`appOnly<T extends ParamType>(type: T): AppOnlyParam<T>`} compact>

A param only your app sets, never a link: `params: { sql: String, autorun: appOnly(Boolean) }`. Use it for anything a link must not be able to turn on, such as a query that runs as it opens. Jali leaves it out of every address it writes (the address bar, Copy link, Back and Forward) and drops it from every link it reads, even when the link holds a value it can't read. What the app gave stays where the app gave it: Back and Forward keep it on a pane that is still open, and a reload keeps what the preset the address names gave a pane, when the pane is exactly the preset's (the same id, showing the same object). A link that changes the pane gets none. It is optional, since a pane opened from a link has none, and it is not part of what the pane shows: `query({ sql, autorun: true })` and `query({ sql })` are the same object.

<Params>
<Param name="type" type="ParamType" required>How to read it when your app gives it: `Number`, `String`, `Boolean`, `oneOf(...)` or a function.</Param>
</Params>

<Returns type="AppOnlyParam<T>" />

</Entry>

<Entry name="oneOf" kind="function" from="jali" signature={`oneOf<const V extends readonly (string | number)[]>(...values: V): OneOf<V[number]>`} compact>

A param that is one of a few values: `oneOf("open", "closed")` gives `"open" | "closed"`. Values are compared as text, so `oneOf(10, 25)` reads `"25"` from a link as `25`. Any other value can't be read, and the ref doesn't open.

<Params>
<Param name="...values" type="(string | number)[]" required>The values it can be.</Param>
</Params>

<Returns type="OneOf<V[number]>">A reader, with the values as `values`.</Returns>

</Entry>

## Commands and keys

<Entry name="listCommands" kind="function" from="jali" signature={`listCommands(jali: Jali): readonly ListedCommand[]`} example={commandsCode} exampleFile="toolbar.ts">

Every command a person can run from a menu now, in the palette's order: the focused pane's own commands first (keys `pane:<id>`), then the instance's and your own `commands`. Each has its `title`, `group`, `keys` label for this platform, `disabled` and the `reason`, and `run`. For an app with its own command menu (no `palette()` feature).

It is worked out on every call, and returns the same array (and the same entries, each with the same `run`) until something it lists changes. So in React it is a store snapshot as it is: `useSyncExternalStore(jali.subscribe, () => listCommands(jali))` re-renders only when the list changes. What it lists can change without a change of state, when an `allow` rule reads your own data: call it again then.

<Returns type="readonly ListedCommand[]" />

</Entry>

## Words

<Entry name="en" kind="constant" from="jali" signature={`const en: Messages`} example={messagesCode} exampleFile="messages.ts">

Jali's English messages: every word it shows or says, by area (`announcements`, `toasts`, `commands`, `commandGroups`, `keys`, `palette`, `chooser`, `confirmDiscard`, `settings`, `tabs`, `shelf`, `pane`, `peek`, `panes`, `page`, `drop`). An instance made without `messages` says these words. A curated page's own words (the `page` area, and the announcements, commands and toast only a page uses) come with the page from `definePage`, so an instance without a page has none of them in `jali.messages`, and an app that doesn't import `en` doesn't ship them. Spread it to start a translation. A message that needs values is a function, such as `en.announcements.closed(pane)`; a message with a bold part takes `bold` and returns its parts in order.
