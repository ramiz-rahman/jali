React components and hooks for an instance made with [jali](/reference/core). React 18.2 or later (18 or 19) is a peer dependency; nothing else is. Jali's icons are in the package. See [Icons](#icons).

<Install packages="jali" />

Styles: `jali/styles.css` is Jali's default theme and the instance's styles; `jali/theme.css` is the theme alone; `jali/tailwind.css` points the tokens at your Tailwind theme. See [Tokens](/reference/tokens).

## Start here

<Entry name="JaliRoot" kind="component" from="jali/react" signature={`<JaliRoot jali={jali} icons? overlays? settingsExtra?>{children?}</JaliRoot>`} example={appCode} exampleFile="App.tsx">

Draws an instance: its panes, "Discard unsaved changes?", the live region, and the dialogs of the features it has: the command palette (`palette()`), Settings (`settings()`) and the "Add to tabs of…" chooser (`chooser()`). See [Features](/reference/features). While it is mounted, it starts the instance's keys, Back and Forward, theme and saving (<Ref to="Jali" page="/reference/core/types" />'s `start`), and stops them when it unmounts.

`<JaliRoot jali={jali} />` is a whole app. To add your own chrome, pass children and put `<JaliView />` where the panes go.

The root is a `<div data-jali>` that the instance attaches to, so focus, drag and F6 stay inside it. The dialogs render after it, in a `<div data-jali-layer>` (styled `display: contents`), which counts as the instance's for its keys. Each dialog is modal: focus goes into it, Tab stays inside it, the root is `inert` while it is open, and focus goes back where it was when it closes. Mark your own chrome inside it with `data-jali-chrome` and Jali never pulls focus out of it.

Two things are yours to render. **The shelf** (tucked panes as chips): put <Ref to="Shelf" /> in your status line or footer, or tucked panes have nowhere to come back from but ⌘K "Show a pane from the shelf". **Toasts**: Jali sends them as the `toast` event, `useJaliEvent("toast", show)` (closes and tucks come with Undo, which ⌘K ⌘Z also runs) and shows none itself; render them with your toaster in `overlays`.

<Params title="Props">
<Param name="jali" type="Jali" required>The instance, from `createJali`.</Param>
<Param name="children" type="ReactNode" default="<JaliView />">Rendered inside the root: `<JaliView>` and your chrome.</Param>
<Param name="overlays" type="ReactNode">Rendered after the root: things that must sit outside the instance, such as a toaster. Focus is never pulled back from outside the root. While one of Jali's dialogs is open they are inert, as the instance behind it is, so a toast's Undo can't be reached until it closes; Jali's own announcements are still heard. They sit in an element of their own (`[data-jali-overlays]`, `display: contents`), so a toaster lays out as it would without it.</Param>
<Param name="icons" type="Partial<JaliIcons>">Your own icons for any of the names Jali draws (`{ close: MyClose }`); the others stay Jali's. See [Icons](#icons).</Param>
<Param name="settingsExtra" type="ReactNode">Your own settings, as `<fieldset>`s with a `<legend>`, shown at the end of the Settings panel. Store their values yourself. A row that is a radio or checkbox and its words matches Jali's as `<label className="jali-setting">` (the `settingRow` part).</Param>
<Param name="aria-label" type="string">The instance's name, over `createJali({ label })`, read at every render. It names Jali's landmark, and each landmark inside carries it.</Param>
<Param name="aria-labelledby" type="string">The id of a visible heading that names the instance; the landmarks inside carry its text.</Param>
<Param name="onError" type="(error: unknown) => void">Hears a throw in your code inside the root or in Jali's own parts. The root shows "… could not be shown" with Retry in place of what failed, and your app around it stays. Giving the root another instance clears the failure and renders the new instance, without mounting your healthy children again. A dialog that throws closes itself, as Esc would, and reports here, so the next dialog opens normally. A pane's own failures go to `onPaneError`.</Param>
<Param name="...rest" type="HTMLAttributes<HTMLDivElement>">Passed to the root `<div>` (`className`, `style`, `id`). `ref` and `data-jali` are Jali's.</Param>
</Params>

</Entry>

<Entry name="JaliView" kind="component" from="jali/react" signature={`<JaliView />`} example={composeCode} exampleFile="App.tsx">

The panes, or the curated page while one is open. Takes no props. `<JaliRoot>` renders it when it has no children; place it yourself when you add chrome.

</Entry>

## Defining panes and pages

<Entry name="definePane" kind="function" from="jali/react" signature={`definePane(kind: string, options: PaneOptionsReact): Pane`} example={kindsCode} exampleFile="kinds.tsx">

Defines a kind of pane: what it shows (its params), its title and sizes, and the component that renders it. Pass your kinds to `createJali({ panes })`.

The result is also how you name an object of the kind: `orderKind({ id: 1041 })` is the [ref](/get-started/key-concepts#ref) `{ kind: "order", params: { id: 1041 } }`, to open, peek, select or put in a layout. When the kind declares `params`, the call is typed: a missing required param, a wrongly typed one or one the kind doesn't declare is a type error. Params are declared with `Number`, `String`, `Boolean`, <Ref to="oneOf" page="/reference/core" /> and <Ref to="optional" page="/reference/core" />, imported from `jali`.

<Params>
<Param name="kind" type="string" required>The kind's name. Every pane of this kind carries it, and links name it.</Param>
<Param name="options" type="PaneOptionsReact" required>

Everything in <Ref to="PaneOptions" page="/reference/core/types" /> (`params`, `title`, `width`, `height`, `shows`, `identity`, `scratch`, `inRecent`, `holdWhileResizing`, `follow`, `selects`), and:

<ChildParams label="view fields">
<Param name="Component" type="ComponentType<PaneProps<P>>" required>Renders the pane's content. It stays mounted while the pane is folded, tabbed, tucked or moved.</Param>
<Param name="Loading" type="ComponentType<PaneProps<P>>">Shown while `Component` suspends (for example, it reads data with `use()`). It gets the same props. Default: a quiet "Loading…". The pane's activity is `"loading"` meanwhile.</Param>
<Param name="Missing" type="ComponentType<MissingProps>">Shown in place of `Component` when the pane's params can't be read: a required one missing, or a value its type can't read. It gets <Ref to="MissingProps" />, so it can explain in the kind's own words and offer a way on. Render it from `Component` too, for params that read but name nothing. Default: Jali's own message, naming the param.</Param>
<Param name="icon" type="JaliIcon">The kind's icon in the header, tab and shelf: any component that takes `{ size, className, "aria-hidden" }`, such as Phosphor's `FileTextIcon`, which matches Jali's own. Jali passes `size` and `aria-hidden`, never a weight, so your icon set's default or its context decides it. Without one, the `defaultKind` icon (a square).</Param>
</ChildParams>

</Param>
</Params>

<Returns type="Pane<P>">The kind, callable: `(params) => ObjectRef`.</Returns>

</Entry>

<Params title="Props">
<Param name="problems" type="readonly ParamProblem[]" required>Each param that is missing (`value` undefined) or holds a value its type can't read. Empty when your own `Component` renders `Missing` for params that read but name nothing.</Param>

<Entry name="PaneProps" kind="type" from="jali/react" signature={`interface PaneProps<P = Params>`} example={noteCode} exampleFile="order-note.tsx">

What a kind's `Component` gets. Components below it read the same with <Ref to="usePane" />. To type a component written apart from its kind, declare the params first and pass their declaration: `const orderParams = { id: Number }`, then `PaneProps<typeof orderParams>` (`params` is `{ id: number }`). `PaneProps<{ id: number }>`, the params' own type, also works.

Keys: content first. Claim the keys you use with `event.preventDefault()` (J and K, Space, Enter, ⌘Z for your own undo, the first Esc) and let the rest bubble; single character keys must act only while your content has focus. Content that needs every key (an editor) marks itself `data-pane-keys="content"`; the instance then takes only F6 and Shift+F6 there.

<Param name="params" type="P" required>What the pane shows, read with the kind's `params` types. A ref missing a required param, or holding a value its type can't read, never gets here: its pane shows the kind's `Missing`, or a message naming the param.</Param>
<Param name="node" type="PaneNode" required>The layout node, with the full ref (`node.ref`). In the peek sheet, a node that is not in the layout.</Param>
<Param name="paused" type="boolean" required>The pane is hidden: tabbed away, tucked, folded, or behind a maximised pane. Pause subscriptions and timers; keep state.</Param>
<Param name="focused" type="boolean" required>The pane has focus.</Param>
<Param name="inPeek" type="boolean" required>Rendered in the peek sheet rather than a pane.</Param>
<Param name="openBeside" type="(ref: ObjectRef, options?: OpenBesideOptions) => ActionResult" required>Open `ref` beside this pane; focus stays here. The selected item opens a following detail (kept if one already follows); another link replaces this pane's earlier plain link of the same kind. `{ edge: "bottom" }` opens it below this pane; any edge, as on screen (see <Ref to="OpenBesideOptions" page="/reference/core/types" />). Returns what `jali.actions.openBeside` does: `pane` is the pane that shows `ref`.</Param>
<Param name="openHere" type="(ref: ObjectRef) => ActionResult" required>Show `ref` in this pane. If it is open elsewhere, that pane is focused instead. In the peek sheet, which has no pane of its own, `{ ok: false, reason: "unavailable" }`.</Param>
<Param name="peek" type="(ref: ObjectRef | null) => ActionResult" required>Open or move the peek sheet; `null` closes it. When this pane has a following detail of the ref's kind on screen, the detail shows the item instead of the peek sheet, and no sheet opens (see <Ref to="JaliActions" page="/reference/core/types" />).</Param>
<Param name="select" type="(ref: ObjectRef | null, options?: { inResults?: boolean }) => ActionResult" required>Report the item a list is on. An open peek from this pane follows it at once; this pane's following detail once it rests. `{ inResults: false }`: the filter no longer shows `ref`. Report the selection before opening it, so the opened pane is linked to it.</Param>
<Param name="dismiss" type="() => void" required>Close this pane quietly, with no undo toast: for the launcher.</Param>
</Params>

</Entry>

## Inside a pane

Each of these acts for the pane it is called in, from any depth inside the kind's component.

<Entry name="usePane" kind="hook" from="jali/react" signature={`usePane(kind?: Pane): PaneProps<params of kind>`} compact>

The pane's <Ref to="PaneProps" />, for components below the kind's own: `const { params, openBeside } = usePane(order)`, with `params` typed from the kind, no cast. In development, a component in a pane of another kind is an error. Without a kind, the params are plain values (`Params`), for a component any kind renders. Throws outside a pane.

<Returns type="PaneProps<P>" />

</Entry>

<Entry name="useActivity" kind="hook" from="jali/react" signature={`useActivity(activity: PaneActivity | undefined): void`} compact>

Report what the pane is doing (`"loading"`, `"working"`, `"live"`, `"needs-you"`, `"error"` or `"idle"`), for its header, its tab, the shelf and the status line. `"working"` is work the person waits for; `"live"` is ongoing, healthy work that is meant to go on, such as recording, streaming or playback, and reads "Live" rather than "Working". `undefined` clears it, the same as `"idle"`, and so does the component unmounting. Reported again whenever it changes.

Several components in a pane may each report: the pane shows the most pressing (error, needs you, working, loading, live), and one unmounting clears only its own.

</Entry>

<Entry name="useUnsaved" kind="hook" from="jali/react" signature={`useUnsaved(what: string | null | false | undefined): void`} compact>

Report unsaved work in words (`"an unsaved query"`), or a falsy value once it is saved, so `useUnsaved(dirty && "an unsaved note")` works. While a pane has some, closing it, closing others, a preset or showing another object in it asks first; a following detail keeps its object. Moving, tabbing, folding and tucking never ask. Cleared when the component unmounts.

Several components in a pane may each report: the pane has unsaved work while any of them has some, and the question lists every distinct text. One saving or unmounting clears only its own.

</Entry>

<Entry name="useTitle" kind="hook" from="jali/react" signature={`useTitle(title: string | null | undefined): void`} compact>

Name the pane from its data: `useTitle(customer.data?.name)` shows "Acme Ltd" rather than the kind's "Customer 12". While set, it replaces the kind's `title` in the header, the tab, the shelf, the palette, the switcher, announcements and `jali.model().pane(id)?.title`, and the peek sheet while it shows the same object. In a curated page, the view's label still names the pane, and this title is shown beside it. `null` or `undefined` goes back to the kind's title.

When several components in a pane set a title, the innermost one wins (after the first mount, the one mounted last); one unmounting goes back to the next.

It is cleared when the component unmounts and when the pane shows another object, then set again from the next render. It is not saved, so a reload shows the kind's title until the data loads.

In the peek sheet's own content, it names the sheet, for the object the sheet shows: on a curated page in Single view, where links peek, the sheet says "Acme Ltd" rather than "Customer 12" even when no pane shows that customer. The sheet takes, in order: its own content's `useTitle`, then that of a pane in the layout showing the same object, then the kind's `title`. Its own name goes when the sheet closes or shows another object.

</Entry>

<Entry name="usePaneAttributes" kind="hook" from="jali/react" signature={`usePaneAttributes(attributes: Record<\`data-\${string}\`, string> | null | undefined): void`} compact>

Mark the pane from its data with `data-*` attributes, so your styles can tell it apart: `usePaneAttributes({ "data-connection": "production" })` on a query pane connected to production. Jali puts them on everything that stands for the pane: its section, its tab in any strip (folded and tucked too), its shelf chip, its entry in the phone's pane switcher, the tab and shelf menus, and the peek sheet while it shows the pane's object. Jali gives them no style of its own.

When several components in a pane set attributes, the innermost one's are used (after the first mount, the one mounted last); one unmounting goes back to the next.

Only `data-*` names are kept, and not the ones Jali's own parts use (`data-pane`, `data-tab`, `data-focused`, `data-jali-*` and the rest). `null` or `undefined` clears them. They are cleared when the component unmounts and when the pane closes or shows another object, then set again from the next render. They are not saved. The peek sheet's own content can't set them.

</Entry>

<Entry name="useHeaderActions" kind="hook" from="jali/react" signature={`useHeaderActions(controls: ReactNode): void`} compact>

Put the pane's own controls in its header. Jali places them in `.jali-pane-tools`, in this order: the grip, the title (or tabs), Following / Kept, your controls, then Jali's buttons. Pass them on every render, like any JSX. `null` takes them away, as does the component unmounting. One set shows per pane, chosen as a title is: of calls mounted together, the innermost call's; after that, the latest mounted call's that has controls. Each call is its own, so a component that unmounts takes only its controls away, and the previous call's show again.

They render inside the pane's context, so the pane's hooks work in them, as do providers above `<JaliRoot>`. A provider inside your own component doesn't reach them.

A narrow header gives way before its title gets shorter than a few characters: first Jali's tuck, maximise, full screen and pop out move into the pane's menu, then your controls are hidden too (`data-narrow="tools"`) and the menu lists the pane's commands (`useCommands`) in their place. So give each control a command as well, or it can't be reached in a very narrow pane. The peek sheet has no header, so the controls aren't shown there.

</Entry>

<Entry name="useCommands" kind="hook" from="jali/react" signature={`useCommands(commands: readonly PaneCommand[]): void`} compact>

The commands this pane lists first in the palette while it is focused. Pass them on every render: they are listed again only when an id, title, keys label or disabled reason changes, and each runs the latest `run` it was given, so `run` can close over current state. Removed when the component unmounts.

Several components in a pane may each add commands: they are listed in render order (a parent's before its children's), the first of a repeated id kept, and one unmounting removes only its own.

</Entry>

<Entry name="usePaneState" kind="hook" from="jali/react" signature={`usePaneState<T>(key: string, initial: T, options?: PaneStateOptions<T>): [T, (next: T | ((prev: T) => T)) => void]`} example={paneStateCode} exampleFile="OrdersTable.tsx">

State the instance keeps for a pane: it survives the pane being tabbed, folded, tucked or moved, and a reload (saved on this device 400 ms after it changes). It is dropped when the pane closes for good or shows another object, and when the person discards the pane's unsaved work. It belongs to the object the pane shows, not to the pane's id: a pane that shows another object under the same id (after a reload, or a new pane under a closed pane's id) starts from `initial`, and an undo that brings the pane back brings its state back. Use it for what a person expects back (a sort, a draft, a scroll position) and React state for the rest.

In the peek sheet there is no pane, so the state is local and goes with the sheet.

<Params>
<Param name="key" type="string" required>The value's name within the pane.</Param>
<Param name="initial" type="T" required>Used until a value is set. Read once, as with `useState`: a new object on each render doesn't change the value, and an updater's `prev` is the first `initial` while nothing is stored. Must be JSON.</Param>
<Param name="options" type="PaneStateOptions<T>">`parse`, to check what was stored before it is used as `T`.</Param>
</Params>

<Returns type="[T, (next: T | ((prev: T) => T)) => void]">The value, and a setter that takes a value or an updater. Values must be JSON.</Returns>

</Entry>

<Entry name="PaneStateOptions" kind="type" from="jali/react" signature={`interface PaneStateOptions<T> {\n  parse?: (stored: unknown) => T | undefined;\n}`} compact>

How <Ref to="usePaneState" /> reads a stored value. Stored state was written by an earlier version of the app, or edited by hand, so it isn't trusted as `T`: `parse` gets what storage held and returns the value to use, or `undefined` to use `initial`. A parse that throws counts as `undefined`. A rejected value stays stored until the pane sets its own. Each stored value is parsed once, so a parse that builds a new object still gives the same value on every render.

</Entry>

## The instance in React

<Entry name="useJali" kind="hook" from="jali/react" signature={`useJali(): Jali`} compact>

The instance from the nearest `<JaliRoot>`: its `actions`, `on`, `getLayout` and `setLayout`, `keymap`, `presets` and state. Reading it does not subscribe; use `useJaliState` or `useJaliModel` for values that change. Throws outside `<JaliRoot>`.

<Returns type="Jali" />

</Entry>

<Entry name="useJaliState" kind="hook" from="jali/react" signature={`useJaliState<T>(select: (s: JaliState) => T, isEqual?: (a: T, b: T) => boolean): T`} example={hooksCode} exampleFile="StatusLine.tsx">

Subscribes to one value of the state (<Ref to="JaliState" page="/reference/core/types" />). The component re-renders when that value changes, compared with `isEqual` (`Object.is` unless given). The state keeps each field's object while it is the same, so picking `s.view` or `s.selection` re-renders only when that changes. A selector may return a new object or array; pass your own equality function (one that compares its values, say) to re-render only when one of them changed.

<Params>
<Param name="select" type="(s: JaliState) => T" required>Picks the value.</Param>
<Param name="isEqual" type="(a: T, b: T) => boolean">Whether two picks are the same. Default `Object.is`.</Param>
</Params>

<Returns type="T" />

</Entry>

<Entry name="useJaliModel" kind="hook" from="jali/react" signature={`useJaliModel(): JaliModel
useJaliModel<T>(select: (m: JaliModel) => T, isEqual?: (a: T, b: T) => boolean): T`} example={iconCode} exampleFile="OpenPanes.tsx">

The layout as it is on screen, subscribed: every pane, with its title and where it is (<Ref to="JaliModel" page="/reference/core/types" />). A new object only when a pane changed, and each pane keeps its object while it is the same. With a selector, only what it picks, re-rendering when that changes by `isEqual`: `useJaliModel((m) => m.pane(id)?.where)` re-renders only when that pane moves.

<Returns type="JaliModel" />

</Entry>

<Entry name="useJaliEvent" kind="hook" from="jali/react" signature={`useJaliEvent(event: JaliEvent, handler: (e: JaliEvents[event]) => void): void`} compact>

It always calls the latest `handler`, so an inline function is fine, and stops listening on unmount. Typed by the app's instance once it is registered (`Register`). See <Ref to="JaliEvents" page="/reference/core/types" />.

</Entry>

<Entry name="useJaliTheme" kind="hook" from="jali/react" signature={`useJaliTheme(): "light" | "dark"`} compact>

The theme in use: the person's setting, or the system's when they chose "System". For a toaster or anything else of yours that needs to match.

<Entry name="useJaliShortcut" kind="hook" from="jali/react" signature={`useJaliShortcut(id: string): string`} compact>

## Parts

Chrome of your own goes inside `<JaliRoot>`, around `<JaliView />`: the root renders the dialogs, the live region and the full-screen layer for every way of using Jali. These parts are for that chrome; each must be inside `<JaliRoot>`, and none takes props unless shown.

<Entry name="PageBar" kind="component" from="jali/react" signature={`<PageBar />`} compact>

A curated page's controls, for your top bar: the Single / Split view switch, in Split view the "N opened panes" group with Back to the page, and Reset. Renders nothing while no page is open.

<Entry name="Shelf" kind="component" from="jali/react" signature={`<Shelf />`} compact>

## Icons

Jali draws its own chrome icons from a map of names (`JaliIcons`). Its defaults are in the package (Phosphor's regular weight, copied, so you install no icon library), and `<JaliRoot icons>` replaces any of them. A kind's icon is the kind's own (`definePane({ icon })`). The host's buttons (your top bar, ⌘K, settings, a switcher) are yours and use your icons already. See [Your own icons](/guides/theming#your-own-icons).

```ts
 // Jali's icons; icons={...} replaces any of them
 // Jali's full set, to spread under your own
```
