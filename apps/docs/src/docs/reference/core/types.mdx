Import any of these with `import type { … } from "jali";`. Functions that use them are on [jali](/reference/core) and [The layout namespace](/reference/core/layout).

## The layout tree

<Entry name="Layout" kind="type" from="jali" signature={`interface Layout { version: 1; root: LayoutNode; overlay?: Overlay }`} compact>

An instance's arrangement: a tree of rows, columns and tab stacks of panes. The tree is the arrangement the person made; folds, tucks, tab choices and hidden panes are recorded in `overlay`, so they can be undone without losing a slot. This is what `?l=` holds.

<Params title="Fields">
<Param name="version" type="1" required>Always `1`.</Param>
<Param name="root" type="LayoutNode" required>The top node. A single pane is a valid root.</Param>
<Param name="overlay" type="Overlay">What the layout and the person did on top of the tree. Written by the operations; leave it out when you build a layout.</Param>
</Params>

</Entry>

<Entry name="LayoutNode" kind="type" from="jali" signature={`type LayoutNode = PaneNode | StackNode | SplitNode`} compact>

One node of the tree. Every node has an `id` (unique in the layout), a `size`, and optionally `userSized` (the person dragged it) and `base` (the size a divider reset returns to).

</Entry>

<Entry name="PaneNode" kind="type" from="jali" signature={`interface PaneNode { type: "pane"; id; size; ref: ObjectRef; … }`} compact>

A pane: one object, shown by its kind's component.

<Params title="Fields">
<Param name="type" type={`"pane"`} required />
<Param name="id" type="NodeId" required>Unique in the layout. In a curated page a role's pane id equals its role id.</Param>
<Param name="size" type="Size" required>Its share of its split.</Param>
<Param name="ref" type="ObjectRef" required>What it shows.</Param>
<Param name="userSized" type="boolean">The person sized it with a divider.</Param>
<Param name="base" type="Size">The size a divider reset returns to. Carried in the layout and the URL.</Param>
<Param name="linkedTo" type="NodeId">The pane it was opened from. Closing that pane drops the link.</Param>
<Param name="follows" type="boolean">It shows the object selected in `linkedTo` and changes in place when the selection moves. At most one per source and kind.</Param>
<Param name="kept" type="boolean">Kept by the person: never reused for another object, never following, the last to fold.</Param>
<Param name="pinned" type="boolean">A pinned tab: first in its tab group, left open by Close other tabs and Close tabs to the right, and still pinned if it leaves the group and joins another.</Param>
<Param name="born" type="number">Its age, rising with each open; older panes fold first when over the cap. Panes without one come before new ones.</Param>
<Param name="role" type="string">The view of a curated page it fills ("borrower"). Panes without a role were opened by the person.</Param>
<Param name="priority" type={`"primary" | "supporting"`}>Supporting panes give way first when room runs out; a primary pane never folds while another can.</Param>
</Params>

</Entry>

<Entry name="SplitNode" kind="type" from="jali" signature={`interface SplitNode { type: "row" | "column"; id; size; children: LayoutNode[] }`} compact>

Children side by side (`"row"`) or one above another (`"column"`), sharing the space by their sizes. Splits nobody sized share by the panes' comfortable and maximum widths; once the person sizes a child, the split keeps its proportions exactly.

</Entry>

<Entry name="StackNode" kind="type" from="jali" signature={`interface StackNode { type: "stack"; id; size; children: PaneNode[]; active: NodeId; origin?: "user" }`} compact>

A tab group the person made (by merging, a centre drop or a new tab). Groups made by folding are not in the tree; they exist in `overlay`. `active` is the shown tab; `origin` is optional (`"user"` when set); leave it out in hand-written layouts.

</Entry>

<Entry name="Size" kind="type" from="jali" signature={`type Size = { px: number } | { weight: number }`} compact>

A share of a split (`weight`, relative to the siblings) or a fixed length in pixels. Divider drags store weights, scaled so the ones a drag sets average 1.

</Entry>

<Entry name="NodeId" kind="type" from="jali" signature={`type NodeId = string`} compact>

A node's id: 1 to 128 letters, digits, `_`, `.`, `:` or `-` (`orders`, `pane-3`, `detail:7`). Every id Jali and the builders make fits; a layout from outside with any other id is refused.

</Entry>

<Entry name="ObjectRef" kind="type" from="jali" signature={`interface ObjectRef { kind: string; params: Record<string, string | number | boolean> }`} compact>

What a pane shows: a kind and the params that name the object (`{ kind: "order", params: { id: 1041 } }`). Params must be strings, finite numbers or booleans.

</Entry>

<Entry name="Axis" kind="type" from="jali" signature={`type Axis = "row" | "column"`} compact>

The direction of a split.

</Entry>

<Entry name="Edge" kind="type" from="jali" signature={`type Edge = "left" | "right" | "top" | "bottom"`} compact>

A side of a pane: where to open or drop. In actions and commands it is a side of the screen, in either reading direction. The layout operations (`layout.drop`, `layout.open`, `layout.split`) take a side in the tree instead: `"left"` is before, `"right"` after, which right to left is the other side of the screen.

</Entry>

<Entry name="Direction" kind="type" from="jali" signature={`type Direction = "ltr" | "rtl"`} compact>

The reading direction an instance lays its panes out in (`jali.get().dir`, `createJali({ dir })`). Right to left, a row's first child is at the right: the same tree, mirrored on screen.

</Entry>

<Entry name="Overlay" kind="type" from="jali" signature={`interface Overlay { tucks; folds; shown; hidden? }`} compact>

What sits on top of the tree. Written by the operations; read it, don't write it.

<Params title="Fields">
<Param name="tucks" type="{ pane: NodeId; home: NodeId; seq: number }[]" required>Panes tucked into another pane (their home), in order.</Param>
<Param name="folds" type="NodeId[]" required>Slots folded for room, in order. The ids are opaque.</Param>
<Param name="shown" type="Record<NodeId, NodeId>" required>The chosen tab of each folded or tucked group, keyed by the group's home pane.</Param>
<Param name="hidden" type="NodeId[]">Panes taken off screen with no tab and no slot (a curated page's views in the tabs).</Param>
</Params>

</Entry>

<Entry name="ViewState" kind="type" from="jali" signature={`interface ViewState { focused?: NodeId; zoomed?: NodeId; scroll?: Record<NodeId, number>; peek?: ObjectRef; focusHistory: NodeId[] }`} compact>

What the person is looking at, apart from the layout.

<Params title="Fields">
<Param name="focused" type="NodeId">The pane with focus (the accent edge).</Param>
<Param name="zoomed" type="NodeId">The maximised pane. In the URL as `zoom`.</Param>
<Param name="scroll" type="Record<NodeId, number>">How far each row that scrolls has scrolled, by the row's id, in px along its content, set where the row comes to rest. In the URL as `scroll` (`week:732`); a strip at its start writes nothing, and scrolling replaces the history entry.</Param>
<Param name="peek" type="ObjectRef">What the peek sheet shows. In the URL as `peek`.</Param>
<Param name="focusHistory" type="NodeId[]" required>Panes most recently focused first.</Param>
</Params>

</Entry>

<Entry name="PaneKind" kind="type" from="jali" signature={`interface PaneKind { kind; title(ref); minWidth; minHeight; comfortableWidth?; maxWidth?; comfortableHeight?; maxHeight?; checkParams? }`} compact>

The part of a kind the layout operations read, from `kinds.registry()`. The sizes are explained under <Ref to="PaneKindBase" />. `checkParams(params)`, set for a kind that declares `params`, says what is wrong with a ref's params (a required param missing, a value its type can't read), or returns `undefined`; <Ref to="layout.validate" page="/reference/core/layout" /> rejects a layout holding such a ref, so a link to it opens as broken.

</Entry>

<Entry name="KindRegistry" kind="type" from="jali" signature={`type KindRegistry = Record<string, PaneKind>`} compact>

Kinds by name, as the layout operations take them (`kinds.registry()`).

</Entry>

<Entry name="LayoutContext" kind="type" from="jali" signature={`interface LayoutContext { fit: FitOptions; paneCap: number; dir?: Direction }`} compact>

Everything a layout operation needs besides the layout. For an instance: `{ fit: { ...jali.get().area, gap: GAP, kinds: jali.env.kinds.registry() }, paneCap: jali.get().settings.paneCap, dir: jali.get().dir }`. `paneCap` is the most panes on screen before the oldest folds (the `paneCap` setting). `dir: "rtl"` mirrors the rects `resolve` returns, so they stay screen coordinates; the tree and the fit are the same.

</Entry>

<Entry name="FitOptions" kind="type" from="jali" signature={`interface FitOptions { width: number; height: number; gap: number; kinds: KindRegistry }`} compact>

The room: the instance's inner size in pixels, the gap between panes (6 in an instance), and the kinds.

</Entry>

<Entry name="Rect" kind="type" from="jali" signature={`interface Rect { x: number; y: number; width: number; height: number }`} compact>

A box in pixels, relative to the instance's inner area.

</Entry>

<Entry name="ResolvedLayout" kind="type" from="jali" signature={`interface ResolvedLayout { panes: PaneBox[]; dividers: DividerBox[]; stacks; shelf; scrollers: ScrollerBox[] }`} compact>

What `layout.resolve` returns: `panes` and `dividers` with their rects; `stacks`, the groups made by folding and tucking (`{ id, kind: "fold" | "tuck", homeId, paneIds }`); and `shelf`, every pane behind a tab with why (`{ paneId, homeId, stackId, reason: "tucked" | "folded" | "tab" }`).

</Entry>

<Entry name="PaneBox" kind="type" from="jali" signature={`interface PaneBox { id: NodeId; rect: Rect; stackId?: NodeId; hidden?: "tab" | "zoom" | "off"; clip?: Rect }`} compact>

A pane's place. `hidden`: behind another tab, behind a maximised pane, or `"off"` (hidden by the overlay, with an empty rect).

</Entry>

<Entry name="DividerBox" kind="type" from="jali" signature={`interface DividerBox {\n  parentId: NodeId; index: number; axis: Axis; rect: Rect;\n  min: number; max: number; value: number;\n  neighbours?: [NodeId[], NodeId[]];\n}`} compact>

A divider between child `index` and `index + 1` of split `parentId`. `value` is the first side's length now; `min` and `max` are how far a drag can take it; `neighbours` are the panes on each side.

</Entry>

<Entry name="ScrollerBox" kind="type" from="jali" signature={`interface ScrollerBox { id: NodeId; rect: Rect; contentWidth: number; paneIds: NodeId[] }`} compact>

A row that scrolls sideways (`row({ scroll: "x" }, …)`), as drawn. `rect` is its window on screen; its panes are laid along its content, `contentWidth` long, from `rect.x`. Once scrolled (<Ref to="layout.scrolled" page="/reference/core/layout" />), a strip's panes and dividers carry `clip`: the window they are cut to.

</Entry>

<Entry name="ResolvedStack" kind="type" from="jali" signature={`interface ResolvedStack { id: NodeId; kind: "fold" | "tuck"; homeId: NodeId; paneIds: NodeId[] }`} compact>

A tab group the fit made, not one in the tree: panes folded into a neighbour (`"fold"`) or tucked into their home (`"tuck"`). `homeId` is the pane whose slot holds them.

</Entry>

<Entry name="ShelfEntry" kind="type" from="jali" signature={`interface ShelfEntry { paneId: NodeId; homeId: NodeId; stackId: NodeId; reason: "tucked" | "folded" | "tab" }`} compact>

A pane that is not on screen, listed on the shelf: tucked, folded by the fit, or a background tab of a tucked or folded group. `homeId` is where it shows when put back.

</Entry>

<Entry name="TuckedEntry" kind="type" from="jali" signature={`type TuckedEntry = ShelfEntry & { reason: "tucked" }`} compact>

A pane the person tucked, as the model's `shelf` lists it. Folded panes are never on it: they wait behind their strip's "N folded" chip.

</Entry>

## Writing a layout

<Entry name="LayoutInput" kind="type" from="jali" signature={`type LayoutInput = Layout | Draft | ObjectRef`} compact>

Anything that stands for a layout: a builder's result (`row(...)`), a single ref (a one-pane layout), or a whole `Layout`. `createJali({ layout })`, a preset's `layout` and a page's `build` all take one.

</Entry>

<Entry name="Draft" kind="type" from="jali" signature={`type Draft = PaneDraft | SplitDraft | TabsDraft`} compact>

What the builders return: a layout not yet given ids. Pass it wherever a <Ref to="LayoutInput" /> goes; Jali turns it into a `Layout` (<Ref to="toLayout" page="/reference/core" />). Name it in a function of your own that builds part of a layout.

</Entry>

<Entry name="PaneDraft" kind="type" from="jali" signature={`type PaneDraft = { type: "pane"; ref: ObjectRef; options: PaneNodeOptions }`} compact>

What <Ref to="pane" page="/reference/core" /> returns: one pane, with its options.

</Entry>

<Entry name="SplitDraft" kind="type" from="jali" signature={`type SplitDraft = { type: Axis; options: RowOptions; children: Draft[] }`} compact>

What <Ref to="row" page="/reference/core" /> and <Ref to="column" page="/reference/core" /> return: children side by side (`"row"`) or one above the other (`"column"`).

</Entry>

<Entry name="TabsDraft" kind="type" from="jali" signature={`type TabsDraft = { type: "stack"; options: TabsOptions; children: PaneDraft[] }`} compact>

What <Ref to="tabs" page="/reference/core" /> returns: panes as tabs of one group.

</Entry>

<Entry name="RowOptions" kind="type" from="jali" signature={`interface RowOptions extends SizeOptions { scroll?: "x" }`} compact>

A row's options. `scroll: "x"` makes a row that scrolls sideways: each child keeps its own width (its comfortable width until the person sizes it) and the row scrolls to the rest, so nothing folds. To its parent it needs one child's room; to the pane cap it is one slot. Focusing a pane in it scrolls it into view.

</Entry>

<Entry name="SizeOptions" kind="type" from="jali" signature={`interface SizeOptions { id?: NodeId; weight?: number; px?: number }`} compact>

A builder node's id and size: a share of its parent (`weight`, default 1) or a fixed length (`px`). See <Ref to="row" page="/reference/core" />.

</Entry>

<Entry name="PaneNodeOptions" kind="type" from="jali" signature={`interface PaneNodeOptions extends SizeOptions {\n  linkedTo?; follows?; kept?; pinned?; role?; priority?; hidden?: boolean;\n}`} compact>

The options of <Ref to="pane" page="/reference/core" />.

</Entry>

<Entry name="TabsOptions" kind="type" from="jali" signature={`interface TabsOptions extends SizeOptions { active?: NodeId }`} compact>

The options of <Ref to="tabs" page="/reference/core" />.

</Entry>

## Kinds and pages

<Entry name="PaneOptions" kind="type" from="jali" signature={`interface PaneOptions<P = Params> { params?; title; width?; height?; … }`} compact>

What a kind says about itself, apart from how it renders. In React, `definePane(kind, options)` takes these with `Component` and `icon`.

<Params title="Fields">
<Param name="params" type="ParamTypes">What a ref of the kind holds, and how to read each param back from a link, which can turn values into text: `{ id: Number, tab: optional(String) }` gives the component and `title` `{ id: number; tab?: string }`. A ref missing a required param, or holding a value its type can't read, never reaches the component (see <Ref to="ParamProblem" />). Without `params`, params are plain values.</Param>
<Param name="title" type="string | ((params: P) => string)" required>The pane's title in its header, its tab and the palette.</Param>
<Param name="width" type="PaneWidth" default="{ min: 240 }">

<ChildParams label="width">
<Param name="min" type="number" default="240">The narrowest the content works at, once it adapts. Below it the pane folds into a tab; it is never squeezed past it.</Param>
<Param name="comfortable" type="number" default="min">Where spare space takes the pane first, before any sibling grows past its own.</Param>
<Param name="max" type="number" default="none">The widest the content usefully uses. Spare space past it goes to siblings that can use it; only when every sibling is at its maximum does the pane grow on, and the content keeps its measure. Leave it out for tables and charts.</Param>
</ChildParams>

</Param>
<Param name="height" type="PaneHeight" default="{ min: 160 }">

The same three as `width`, down a column.

<ChildParams label="height">
<Param name="min" type="number" default="160">The shortest the content works at. Below it the pane folds into a tab.</Param>
<Param name="comfortable" type="number" default="min">Where spare height takes the pane first, before any pane above or below grows past its own.</Param>
<Param name="max" type="number" default="none">The tallest the content usefully uses. Spare height past it goes to the panes above and below first; only when every one is at its maximum does the pane grow on. A short, wide pane such as a timeline sets it.</Param>
</ChildParams>

</Param>
<Param name="shows" type="string" default="the kind">The type of object shown, shared by kinds that show the same objects differently. Two panes show the same object when this and their identities match.</Param>
<Param name="identity" type="(params: P) => Identity | undefined" default="every param, compared as text">What makes two panes of this kind the same object (one object, one pane): a value compared as JSON (text, a number, a flag, or a list or record of those). `1` and `"1"` are the same by default. One it can't give (it throws, or gives what JSON can't write, such as a bigint) falls back to the default; `undefined` matches no other pane.</Param>
<Param name="scratch" type="boolean">Every pane is new (a scratch note, a launcher): never matched against an open pane, and left out of Recent unless `inRecent` says otherwise.</Param>
<Param name="inRecent" type="boolean | ((params: P) => boolean)" default="true (false for scratch kinds)">Whether opened objects of this kind go in Recent.</Param>
<Param name="holdWhileResizing" type="boolean">Keep the content as it is during a divider drag and reflow once, on release: for long lists and charts.</Param>
<Param name="allow" type="PaneAllow">What may happen to panes of this kind, for what its content can handle: `{ fullScreen: false }`. A kind can only turn controls off. See <Ref to="PaneAllow" />.</Param>
<Param name="buttons" type="PaneButtons">The buttons in this kind's header, replacing the instance's: a list, or a function that adjusts them (`(defaults) => defaults.filter((b) => b !== "tuck")`). Leave it out for the instance's, or Jali's. See <Ref to="PaneButtons" />.</Param>
<Param name="phone" type={`{ stack?: boolean; place?: "top" | "bottom" }`}>Phones only, in stacked view (`createJali({ phone: { stack: true } })`). `stack: false` keeps panes of this kind out of it, so they show alone. `place` asks for the top or the bottom half; otherwise the pane others were opened from goes above.</Param>
<Param name="follow" type="(selected: ObjectRef) => FollowParams<P> | undefined">What a following pane of this kind shows when its list selects an object of another kind: the params for it, or `undefined` to keep what it shows. `follow: (selected) => ({ symbol: selected.params.symbol })` lets a chart follow a watchlist that selects quotes. A follower of the selected object's own kind shows that object without it. Params given as `undefined` are left out; if the kind can't read the result (a required param missing), the pane keeps what it shows. See [Following a list](/learn/following#followers-of-other-kinds).</Param>
<Param name="selects" type="string">For a list: the kind of the objects it selects (`"quote"` for a watchlist that reports `select(quote(...))`). A pane of this kind with no selection starts on what its follower of that kind shows, when the layout gives it one: at start-up, on a link, after a preset or `setLayout`, in the same change. A follower of another kind gives nothing. See [Following a list](/learn/following#where-a-list-starts).</Param>
</Params>

</Entry>

<Entry name="PaneDefinition" kind="type" from="jali" signature={`type PaneDefinition<P, D> = D & { (params: P): ObjectRef; readonly kind: string }`} compact>

<Entry name="PaneKindBase" kind="type" from="jali" signature={`interface PaneKindBase extends PaneOptions { kind: string }`} compact>

A kind as an instance keeps it: its name and its options. What `createJali({ panes })` takes.

</Entry>

<Entry name="Params" kind="type" from="jali" signature={`type Params = Record<string, ParamValue>`} compact>

A ref's params: plain data, so they fit in a link.

</Entry>

<Entry name="ParamValue" kind="type" from="jali" signature={`type ParamValue = string | number | boolean`} compact>One param's value.</Entry>

<Entry name="ParamType" kind="type" from="jali" signature={`type ParamType = (value: ParamValue) => ParamValue | undefined`} compact>

How to read one param back: `Number`, `String`, `Boolean`, <Ref to="oneOf" page="/reference/core" />, or your own function. `Number` reads text that is a finite number; `Boolean` reads `true`, `false`, `"true"`, `"false"`, `1` and `0`. Your function says it can't read a value by returning `undefined` or `NaN`, or by throwing.

</Entry>

<Entry name="ParamTypes" kind="type" from="jali" signature={`type ParamTypes = Record<string, ParamReader | OptionalParam>`} compact>A kind's `params`, one by one.</Entry>

<Entry name="ParamReader" kind="type" from="jali" signature={`type ParamReader = ParamType | StandardSchemaV1`} compact>

How to read one param: one of Jali's (`Number`, `String`, `Boolean`, `oneOf(...)`, a function), or a Standard Schema of the value from any library that implements it (`z.number()`, `v.picklist([...])`). A schema whose output may be `undefined` (`v.optional(…)`) lets a ref leave the param out, as `optional` does.

</Entry>

<Entry name="Identity" kind="type" from="jali" signature={`type Identity = string | number | boolean | null | readonly Identity[] | { readonly [key: string]: Identity }`} compact>What a kind's `identity` gives for one object: any value JSON writes as it is. Two panes show the same object when their kinds' `shows` and these values, written as JSON, match.</Entry>

<Entry name="ParamsDeclaration" kind="type" from="jali" signature={`type ParamsDeclaration = ParamTypes | StandardSchemaV1`} compact>

What `params` takes: params one by one, or one Standard Schema of the whole object (`v.object({ id: v.number() })`). A schema decides what is valid, and its output is what the pane gets (`ParamsOf` infers it); Jali's codec still decides how values are written in a link, and a value a link carries as text is read as a number or a flag when the schema wants one. A value the schema refuses is a <Ref to="ParamProblem" />, as for Jali's own types. A schema may transform values, but its output must still be params (text, numbers and flags): a field it gives as anything else (an object, a list, a date) is a problem of that param, and the ref keeps what it was given. A schema must validate synchronously. `appOnly` and `link: false` are Jali's own: declare params one by one to use them.

</Entry>

<Entry name="StandardSchemaV1" kind="type" from="jali" signature={`interface StandardSchemaV1<Input = unknown, Output = Input> { readonly "~standard": StandardSchemaV1.Props<Input, Output> }`} compact>

The [Standard Schema](https://standardschema.dev) interface that Zod, Valibot, ArkType and Effect Schema implement, copied into Jali as the spec asks, so Jali depends on none of them.

</Entry>

<Entry name="OptionalParam" kind="type" from="jali" signature={`interface OptionalParam<T extends ParamReader = ParamReader> { readonly optional: T; readonly link?: false }`} compact>

A param a ref may leave out, made by <Ref to="optional" page="/reference/core" />. `link: false` when it stays out of the address.

</Entry>

<Entry name="ParamOptions" kind="type" from="jali" signature={`interface ParamOptions { link?: false }`} compact>

How an optional param travels, the second argument of <Ref to="optional" page="/reference/core" />. `link: false` keeps it out of the address while it stays part of what the pane shows.

</Entry>

<Entry name="AppOnlyParam" kind="type" from="jali" signature={`interface AppOnlyParam<T extends ParamType = ParamType> extends OptionalParam<T> { readonly appOnly: true }`} compact>

A param only your app sets, from <Ref to="appOnly" page="/reference/core" />: optional, and never carried or set by a link.

</Entry>

<Entry name="OneOf" kind="type" from="jali" signature={`type OneOf<V extends string | number> = ((value: ParamValue) => V | undefined) & { readonly values: readonly V[] }`} compact>

A param that is one of a few values, made by <Ref to="oneOf" page="/reference/core" />.

</Entry>

<Entry name="ParamsOf" kind="type" from="jali" signature={`type ParamsOf<T extends ParamTypes> = { [K in Required]: Read<T[K]> } & { [K in Optional]?: Read<T[K]> }`} compact>

The params a kind's code sees, from its declaration: `ParamsOf<{ id: NumberConstructor; tab: OptionalParam<StringConstructor> }>` is `{ id: number; tab?: string }`. Use it as `ParamsOf<typeof orderParams>` to name the type of params declared apart from the kind. Without a declaration, `Params`.

</Entry>

<Entry name="FollowParams" kind="type" from="jali" signature={`type FollowParams<P> = { [K in keyof P]?: ParamValue | undefined }`} compact>

What a kind's `follow` returns: its params, any of which may be missing. Jali checks them against the kind's `params` before the pane shows them.

</Entry>

<Entry name="ParamProblem" kind="type" from="jali" signature={`interface ParamProblem { param: string; value?: ParamValue }`} compact>

A param a ref is missing (`value` is undefined), or holds a value its type can't read. A ref with one never reaches the component: a layout link or saved layout holding it opens as broken, a peek or a page's opened pane with it is left out of the link, and a pane your code opens with it shows a message naming the param. Listed by `PaneKinds.problems`.

</Entry>

<Entry name="PaneKinds" kind="type" from="jali" signature={`interface PaneKinds<D extends PaneKindBase = PaneKindBase>`} compact>

An instance's kinds, as `jali.env.kinds`.

<Members>
<Member name="PaneKinds.register" signature="register(def: D): void">Adds or replaces a kind and bumps `version()`.</Member>
<Member name="PaneKinds.get" signature="get(kind: string): D | undefined">The kind's definition.</Member>

<Entry name="JaliEvents" kind="type" from="jali" signature={`interface JaliEvents<R extends ObjectRef = ObjectRef> { open; close; pin; focus; layout; toast }`} compact>

<Param name="pin" type="{ pane: NodeId; pinned: boolean }" required>A pane's tab was pinned or unpinned, however it happened: the tab menu, `setPinned`, `setLayout`, Back or a link. <Param name="focus" type="{ pane: NodeId | undefined; previous: NodeId | undefined }" required>Another pane is focused.</Param>

An action that did not happen. `message` is what Jali read out to screen readers, when it said anything; a refusal it did not say is silent, as before.

A refusal that asks a question carries `settled`, a promise of how the question ended: with `reason: "unsaved"`, once the person answers "Discard unsaved changes?"; with `reason: "pending"`, once `beforeClose` answers. It resolves with `{ ok: true, pane }` when the action went ahead, or with a refusal when it didn't (`"kept"` after Keep editing, or when a newer question took its place). It never rejects. A host's yes that leads to Jali's own question resolves with that `"unsaved"` refusal, whose `settled` says how the person answered.

```ts
import { forgetSavedLayouts } from "./saved-layouts";

const result = jali.actions.resetLayout();
if (result.ok) forgetSavedLayouts();
else void result.settled?.then((end) => end.ok && forgetSavedLayouts());
```

</Entry>

<Entry name="RefusalReason" kind="type" from="jali" signature={`type RefusalReason = "not-found" | "invalid" | "unavailable" | "single-view" | "not-allowed" | "last-pane" | "blocked" | "nothing-to-do" | "unsaved" | "kept" | "pending"`} compact>

<Params title="Reasons">
<Param name="not-found" type="">The pane (by id or by what it shows), preset or view named is not there.</Param>
<Param name="invalid" type="">What the action was given won't do. <Param name="unavailable" type="">The instance can't do this: no launcher (split, new tab), no curated page, no free layout to go back to.</Param>

</Params>

<Entry name="BeforeClose" kind="type" from="jali" signature={`type BeforeClose = (request: CloseRequest) => boolean | Promise<boolean>`} compact>

The host's close guard, `createJali({ beforeClose })`. Jali asks it before a change removes panes or makes a pane show another object. `true` lets the change happen; `false` keeps the panes (`reason: "kept"`). A promise holds the change (`reason: "pending"`) until it answers. If the layout changed in the meantime, the held change is dropped. A guard that throws or rejects keeps the panes.

It is asked first. If it says yes and a pane still reports unsaved work (`useUnsaved`), Jali's own "Discard unsaved changes?" follows; Discard does not ask the guard again. It is not asked while the instance is made, or for changes that remove nothing (focus, tuck, open beside). A later yes makes the change against the instance as it is then; if the panes it would remove or replace are no longer the ones asked about, the guard is asked again. When Back or Forward is not made in the end (the guard keeps the panes, or the person keeps editing), the address goes back to what is on screen.
