`layout` is a namespace export of `@jali/core`. Every member is pure: the layout you pass is never changed, an operation that does nothing returns the same object, and the workspace's actions are built from these. To write a layout, use the builders (`row`, `column`, `tabs`, `pane`); these work on one. Types such as `layout.OpenResult` and `layout.UndoEntry` are reachable through it as well.

<Entry name="layout.open" kind="function" from="@jali/core" signature={`layout.open(
  layout: Layout, view: ViewState, target: string, edge: Edge,
  ref: ObjectRef, ctx: LayoutContext, linked: boolean,
  place?: Placement, opts?: OpenOptions,
): OpenResult`} example={layoutCode} exampleFile="layout.ts" exampleHighlight="10-11">

Opens `ref` in a new pane at `edge` of `target`, then fits the layout. `openBeside` and `split` are the two common forms.

When there is no room, or the pane cap is passed, what folds is decided now and recorded in the overlay. With no room, the new pane becomes a tab of its source. Over the cap, the oldest pane that is not kept, focused or primary folds. A linked open (not from a selection) reuses the source's earlier plain link of the same kind instead of opening another pane; followers and kept panes are never reused. A linked open keeps focus on `target`; an unlinked one focuses the new pane.

<Params>
<Param name="layout" type="Layout" required>The layout now.</Param>
<Param name="view" type="ViewState" required>Focus, maximise and peek.</Param>
<Param name="target" type="string" required>The source pane's id. Throws `Unknown source pane` when it is not a pane.</Param>
<Param name="edge" type={`"left" | "right" | "top" | "bottom"`} required>Which side of `target`.</Param>
<Param name="ref" type="ObjectRef" required>What the new pane shows. Throws `Unknown pane kind` when its kind is not in `ctx.fit.kinds`.</Param>
<Param name="ctx" type="LayoutContext" required>The room, the gap, the kinds and the pane cap (see <Ref to="LayoutContext" page="/reference/core/types" />). A negative width or height counts as zero. Throws a `RangeError` for a non-finite size or gap, a negative gap, or a cap that is not a positive integer.</Param>
<Param name="linked" type="boolean" required>Whether the new pane is linked to `target` (`linkedTo`). Closing the source drops the link.</Param>
<Param name="place" type="{ target: string; edge: Edge }">Somewhere else to put it: a curated page keeps opened panes after its arrangement. Ignored when `place.target` is not in the layout.</Param>
<Param name="opts" type="{ yields?: boolean; fromSelection?: boolean }" default="{}">`yields: false`: no supporting pane gives way for the new one; short of room, the new pane becomes a tab of its source. `fromSelection`: `ref` is the source's selected row (or what its kind's `follow` shows for it), so the new pane follows the selection, or opens kept when the source already has a follower of that kind.</Param>
</Params>

<Returns type={`{ layout: Layout; view: ViewState; opened: NodeId; mode: "beside" | "replaced" | "tab" }`}>

<Values title="mode">
<Value name="beside">A new pane, on screen.</Value>
<Value name="replaced">An earlier plain link of the same kind now shows `ref` (`opened` is that pane).</Value>
<Value name="tab">A new pane, folded into a tab because there was no room.</Value>
</Values>

</Returns>

</Entry>

<Entry name="layout.close" kind="function" from="@jali/core" signature={`layout.close(layout, view, target, ctx): { layout: Layout; view: ViewState; undo: UndoEntry }`} compact>

Removes a pane. Its space goes to the pane it was opened from when that is a sibling, else the next sibling, else the previous. Links to it are dropped. When it had focus, focus goes to the most recently focused pane still open. The last pane is never closed: the same layout comes back.

<Returns type="{ layout; view; undo }">`undo` holds the layout and view before, for the workspace's undo.</Returns>

</Entry>

<Entry name="layout.closeOthers" kind="function" from="@jali/core" signature={`layout.closeOthers(layout, view, keep, ctx): { layout; view; undo }`} compact>

<Entry name="layout.drop" kind="function" from="@jali/core" signature={`layout.drop(

Moving a tucked pane ends its tuck. Drops that would change nothing return the same layout. Focus moves to `dragged`.

<Entry name="layout.resizeDivider" kind="function" from="@jali/core" signature={`layout.resizeDivider(layout, parentId: string, index: number, deltaPx: number, ctx): Layout`} compact>

Moves the divider after child `index` of split `parentId` by `deltaPx`, clamped to the neighbours' minimums. Sizes are stored as proportions, never fixed pixels, so the split still fills its space after a close or a window resize; each child keeps its earlier size as `base` for a reset. A zero or non-finite delta returns the same layout.

<Returns type="Layout" />

</Entry>

<Entry name="layout.resetDivider" kind="function" from="@jali/core" signature={`layout.resetDivider(layout, parentId, index, ctx): Layout`} compact>

Puts the two sides of a divider back to their `base` sizes (else an equal share), and siblings that a drag only re-expressed back to theirs.

<Returns type="Layout" />

</Entry>

<Entry name="layout.canTuck" kind="function" from="@jali/core" signature={`layout.canTuck(layout, pane, ctx): { ok: true; home: NodeId } | { ok: false; reason: "missing" | "tab" | "hidden" | "last" }`} compact>

Whether `pane` can be tucked, and into which pane (its home): the pane it was opened from when that is on screen next to it, else the nearest pane on screen in a sibling slot before it, else after it, moving out one split level at a time.

<Values title="reason">
<Value name="missing">Not a pane in this layout.</Value>
<Value name="tab">In a tab group, already tucked, or another tuck's home.</Value>
<Value name="hidden">Not on screen.</Value>
<Value name="last">The root pane, the only pane on screen, or no home found.</Value>
</Values>

</Entry>

<Entry name="layout.hide" kind="function" from="@jali/core" signature={`layout.hide(layout, view, pane, ctx): HideResult`} compact>

Takes a pane off screen with no tab and no slot; its neighbours take the space. The tree keeps it, so `show` brings it back in its place and size. A tab is first lifted out beside its group. Tucks behind it, or its own, are dropped. Never the last pane on screen.

<Returns type={`{ ok: true; layout; view } | { ok: false; reason: "missing" | "hidden" | "last" }`}>`"hidden"`: it is hidden already.</Returns>

<Entry name="layout.show" kind="function" from="@jali/core" signature={`layout.show(layout, view, pane, ctx): HideResult`} compact>

Shows a hidden pane in its own place and focuses it. Room is made by folding others, never the pane being shown. `reason: "hidden"` here means it was not hidden.

<Returns type="HideResult" />

<Entry name="layout.replace" kind="function" from="@jali/core" signature={`layout.replace(layout, view, current, incoming, ctx): { layout; view; reshaped: boolean }`} compact>

`incoming` takes `current`'s place exactly (slot, size, tab position, fold and tuck records) and `current` takes `incoming`'s old place, off screen when that was hidden. Every rect stays the same unless `incoming` can't fit the slot; then the layout refits and `reshaped` is true. Focus moves to `incoming`.

<Entry name="layout.setRef" kind="function" from="@jali/core" signature={`layout.setRef(layout, view, id, ref, ctx, opts?: { hold?: boolean }): Layout`} compact>

<Entry name="layout.setKept" kind="function" from="@jali/core" signature={`layout.setKept(layout: Layout, id: NodeId, kept: boolean, opts?: { follow?: boolean }): Layout`} compact>

<Entry name="layout.arrange" kind="function" from="@jali/core" signature={`layout.arrange(layout: Layout, ctx: LayoutContext, options?: ArrangeOptions): Layout`} compact>

A new arrangement of the same panes (same ids, refs, links, pins and keeps), from the room in `ctx` and each kind's size hints, with no sizes anyone chose. What `jali.actions.autoLayout()` uses.

1. **Order:** reading order, each pane followed by the panes opened from it, so a list sits beside its detail.
2. **Columns:** as many as fit across at the kinds' comfortable widths (`width.comfortable`, else `width.min`).
3. **Rows:** a second row in each column when the height holds two of the tallest minimum, never more than two.
4. **The rest:** tabs of the cell holding the pane they were opened from, else of the last cell. `options.focused` stays the shown tab.

The layout as it is when it holds fewer than two panes. Fit the result with `layout.refit`.

<Params title="ArrangeOptions">
<Param name="focused" type="string">The pane to keep shown when it lands in tabs.</Param>
<Param name="maxColumns" type="number">At most this many columns. Default: as many as fit.</Param>
<Param name="maxRows" type="number">At most this many rows in a column, 1 or 2. Default 2.</Param>
</Params>

<Returns type="Layout" />

</Entry>

<Entry name="layout.resolve" kind="function" from="@jali/core" signature={`layout.resolve(layout: Layout, view: ViewState, ctx: LayoutContext): ResolvedLayout`} compact>
