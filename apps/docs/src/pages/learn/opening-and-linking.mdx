A pane never builds the layout itself. It asks the workspace to show an object, with one of three functions it gets as props, and the workspace decides where it goes. That keeps each pane's code small, and links behave the same way in every pane.

## Open beside

`openBeside(ref)` opens the object in a new pane to the right of this one. It is the usual way to follow a link: from a ticket to its customer, from a customer to an order.

Focus stays in the pane you opened from. The person can open three tickets from a list, one after another, without clicking back into the list each time.

The new pane is linked to the one it came from (`linkedTo`). The link is what lets the layout fold sensibly: a linked pane folds behind the pane it came from, and closing that pane drops the link.

## A plain link replaces the last one

When a pane opens an object of the same kind as a link it opened before, the new object replaces the earlier one, in the same pane, at the same size. Click three orders in a row from one customer's list of orders and you see one order pane, showing the last one.

**Why:** a person following links is usually looking for one thing. Without this rule, each click adds a pane, and the screen fills with objects they have already moved past.

The rule has two exceptions. A [pinned](/get-started/key-concepts#linked) pane is never replaced: pin a pane to keep it and open the next one beside it. And a pane following the list's [selection](/get-started/key-concepts#selection) is never reused by a plain link; [Following a list](/learn/following) covers how a detail changes there.

## Open here

`openHere(ref)` shows a different object in this same pane: same place, same size. Use it for navigation inside a pane, such as "next ticket", or for a pane that stands in until the person picks something.

If the object is already open in another pane, that pane is focused instead, and nothing opens twice. If this pane has [unsaved work](/get-started/key-concepts#unsaved-work), the person is asked before it is replaced.

## Peek

`peek(ref)` shows the object in a sheet over the right of the workspace, without adding a pane or changing the layout. `peek(null)` closes it. In a list, Space usually opens it; Esc closes it.

From the sheet, **Pin beside** closes the peek and opens the object beside the pane it was peeked from, and **Open full** makes it the only pane. While the sheet is open, moving the list's selection moves the peek with it.

If the list already has a following detail on screen, Space shows the row in that detail instead of opening a sheet. Two answers to one question would be one too many.

## Turning a plain link into a pane link

Content often has ordinary links in it: a ticket number in a note, a customer name in a table. Keep the `href`, so the browser's own ⌘-click and middle-click still open a new browser tab, and call `openBeside` on a plain click, as the sample above does.

## One object, one pane, on curated pages

On a [curated page](/get-started/key-concepts#curated-page), each object appears once. A link to something that is already one of the page's views goes to that view instead of opening a copy. Two kinds count as showing the same object when they declare the same `shows` type in `definePane` and the same identity:

- if the view is on screen, it is focused;
- if it is behind another tab, its tab is chosen;
- if it is not on screen, it is placed beside the pane the link is in, so the person never loses the pane they followed the link from.

A link to an opened pane that is already on screen focuses that pane.

In Single mode, and for a viewer who works in Single, a link opens as a peek instead. [Curated pages](/learn/curated-pages) explains why.

## What a free workspace does instead

In a workspace without a curated page, where the person builds the layout, `openBeside` does not look for copies. Opening the same customer from two different orders gives two customer panes, one beside each order. Each is part of its own chain of links, and the person may want them side by side.

What stops copies there is the plain-link rule above, and `openHere`, which focuses an object that is already open rather than showing it twice. A list's following detail never opens a second copy of a row either.

## What the workspace says

Every open is announced to screen readers, briefly:

- a new pane: "Ticket 103 opened beside Tickets";
- a link that replaced an earlier one: "Order 9002 shown beside Orders of customer 7";
- no room: "…opened as a tab: not enough room beside…".
