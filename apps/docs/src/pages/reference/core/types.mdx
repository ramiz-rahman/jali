## The layout tree

<Entry name="Layout" kind="type" from="@jali/core" signature={`interface Layout { version: 1; root: LayoutNode; overlay?: Overlay }`} compact>

A workspace's arrangement: a tree of rows, columns and tab stacks of panes. The tree is the arrangement the person made; folds, tucks, tab choices and hidden panes are recorded in `overlay`, so they can be undone without losing a slot. This is what `?l=` holds.

<Params title="Fields">
<Param name="version" type="1" required>Always `1`.</Param>
<Param name="root" type="LayoutNode" required>The top node. A single pane is a valid root.</Param>
<Param name="overlay" type="Overlay">What the layout and the person did on top of the tree. Written by the operations; leave it out when you build a layout.</Param>
</Params>

</Entry>

<Entry name="LayoutNode" kind="type" from="@jali/core" signature={`type LayoutNode = PaneNode | StackNode | SplitNode`} compact>

One node of the tree. Every node has an `id` (unique in the layout), a `size`, and optionally `userSized` (the person dragged it) and `base` (the size a divider reset returns to).

</Entry>

<Entry name="PaneNode" kind="type" from="@jali/core" signature={`interface PaneNode { type: "pane"; id; size; ref: ObjectRef; … }`} compact>

A pane: one object, shown by its kind's component.

<Params title="Fields">
<Param name="type" type={`"pane"`} required />
<Param name="id" type="NodeId" required>Unique in the layout. In a curated page a role's pane id equals its role id.</Param>
<Param name="size" type="Size" required>Its share of its split.</Param>
<Param name="ref" type="ObjectRef" required>What it shows.</Param>
<Param name="userSized" type="boolean">The person sized it with a divider.</Param>
<Param name="base" type="Size">The size a divider reset returns to. Carried in the layout and the URL.</Param>
<Param name="linkedTo" type="NodeId">The pane it was opened from. Closing that pane drops the link.</Param>
<Param name="follows" type="boolean">It shows the object selected in `linkedTo` and changes in place when the selection moves. At most one per source and kind.</Param>
<Param name="pinned" type="boolean">Kept by the person: never reused for another object, never following, the last to fold.</Param>
<Param name="born" type="number">Its age, rising with each open; older panes fold first when over the cap. Panes without one come before new ones.</Param>
<Param name="role" type="string">The view of a curated page it fills ("borrower"). Panes without a role were opened by the person.</Param>
<Param name="priority" type={`"primary" | "supporting"`}>Supporting panes give way first when room runs out; a primary pane never folds while another can.</Param>
</Params>

</Entry>

<Entry name="SplitNode" kind="type" from="@jali/core" signature={`interface SplitNode { type: "row" | "column"; id; size; children: LayoutNode[] }`} compact>

Children side by side (`"row"`) or one above another (`"column"`), sharing the space by their sizes. Splits nobody sized share by the panes' comfortable and maximum widths; once the person sizes a child, the split keeps its proportions exactly.

</Entry>

<Entry name="StackNode" kind="type" from="@jali/core" signature={`interface StackNode { type: "stack"; id; size; children: PaneNode[]; active: NodeId; origin: "user" }`} compact>

A tab group the person made (by merging, a centre drop or a new tab). Groups made by folding are not in the tree; they exist in `overlay`. `active` is the shown tab; `origin` is always `"user"`.

</Entry>

<Entry name="Size" kind="type" from="@jali/core" signature={`type Size = { px: number } | { weight: number }`} compact>

A share of a split (`weight`, relative to the siblings) or a fixed length in pixels. Divider drags store weights.

</Entry>

<Entry name="NodeId" kind="type" from="@jali/core" signature={`type NodeId = string`} compact>

A node's id.

</Entry>

<Entry name="ObjectRef" kind="type" from="@jali/core" signature={`interface ObjectRef { kind: string; params: Record<string, string | number> }`} compact>

What a pane shows: a kind and the params that name the object (`{ kind: "order", params: { id: 1041 } }`). Params must be strings or finite numbers.

</Entry>

<Entry name="Axis" kind="type" from="@jali/core" signature={`type Axis = "row" | "column"`} compact>

The direction of a split.

</Entry>

<Entry name="Edge" kind="type" from="@jali/core" signature={`type Edge = "left" | "right" | "top" | "bottom"`} compact>

A side of a pane: where to open or drop.

</Entry>

<Entry name="Overlay" kind="type" from="@jali/core" signature={`interface Overlay { tucks; folds; shown; hidden? }`} compact>

What sits on top of the tree. Written by the operations; read it, don't write it.

<Params title="Fields">
<Param name="tucks" type="{ pane: NodeId; home: NodeId; seq: number }[]" required>Panes tucked into another pane (their home), in order.</Param>
<Param name="folds" type="NodeId[]" required>Slots folded for room, in order. The ids are opaque.</Param>
<Param name="shown" type="Record<NodeId, NodeId>" required>The chosen tab of each folded or tucked group, keyed by the group's home pane.</Param>
<Param name="hidden" type="NodeId[]">Panes taken off screen with no tab and no slot (a curated page's views in the tabs).</Param>
</Params>

</Entry>

<Entry name="ViewState" kind="type" from="@jali/core" signature={`interface ViewState { focused?: NodeId; zoomed?: NodeId; peek?: ObjectRef; focusHistory: NodeId[] }`} compact>

What the person is looking at, apart from the layout.

<Params title="Fields">
<Param name="focused" type="NodeId">The pane with workspace focus (the accent edge).</Param>
<Param name="zoomed" type="NodeId">The maximised pane. In the URL as `zoom`.</Param>
<Param name="peek" type="ObjectRef">What the peek sheet shows. In the URL as `peek`.</Param>
<Param name="focusHistory" type="NodeId[]" required>Panes most recently focused first.</Param>
</Params>

</Entry>

<Entry name="PaneKind" kind="type" from="@jali/core" signature={`interface PaneKind { kind; title(ref); minWidth; minHeight; comfortableWidth?; maxWidth? }`} compact>

The part of a kind the layout operations read, from `kinds.registry()`. The sizes are explained under <Ref to="PaneKindBase" />.

</Entry>

<Entry name="KindRegistry" kind="type" from="@jali/core" signature={`type KindRegistry = Record<string, PaneKind>`} compact>

Kinds by name, as the layout operations take them (`kinds.registry()`).

</Entry>

<Entry name="LayoutContext" kind="type" from="@jali/core" signature={`interface LayoutContext { fit: FitOptions; paneCap: number }`} compact>

Everything a layout operation needs besides the layout: `store.ctx()`. `paneCap` is the most panes on screen before the oldest folds (the `paneCap` setting).

</Entry>

<Entry name="FitOptions" kind="type" from="@jali/core" signature={`interface FitOptions { width: number; height: number; gap: number; kinds: KindRegistry }`} compact>

The room: the workspace's inner size in pixels, the gap between panes (6 in a store), and the kinds.

</Entry>

<Entry name="Rect" kind="type" from="@jali/core" signature={`interface Rect { x: number; y: number; width: number; height: number }`} compact>

A box in pixels, relative to the workspace's inner area.

</Entry>

<Entry name="ResolvedLayout" kind="type" from="@jali/core" signature={`interface ResolvedLayout { panes: PaneBox[]; dividers: DividerBox[]; stacks; shelf }`} compact>

What `layout.resolve` returns: `panes` and `dividers` with their rects; `stacks`, the groups made by folding and tucking (`{ id, kind: "fold" | "tuck", homeId, paneIds }`); and `shelf`, every pane behind a tab with why (`{ paneId, homeId, stackId, reason: "tucked" | "folded" | "tab" }`).

</Entry>

<Entry name="PaneBox" kind="type" from="@jali/core" signature={`interface PaneBox { id: NodeId; rect: Rect; stackId?: NodeId; hidden?: "tab" | "zoom" | "off" }`} compact>

A pane's place. `hidden`: behind another tab, behind a maximised pane, or `"off"` (hidden by the overlay, with an empty rect).

</Entry>

<Entry name="DividerBox" kind="type" from="@jali/core" signature={`interface DividerBox {\n  parentId: NodeId; index: number; axis: Axis; rect: Rect;\n  min: number; max: number; value: number;\n  neighbours?: [NodeId[], NodeId[]];\n}`} compact>

A divider between child `index` and `index + 1` of split `parentId`. `value` is the first side's length now; `min` and `max` are how far a drag can take it; `neighbours` are the panes on each side.

</Entry>

## Kinds and pages

<Entry name="PaneKindBase" kind="type" from="@jali/core" signature={`interface PaneKindBase { kind; title; ref; minWidth; minHeight; … }`} compact>

A kind without its view. In React, `PaneKindDef` adds `Component` and `icon`.

<Params title="Fields">
<Param name="kind" type="string" required>The kind's name, as in `ref.kind`.</Param>
<Param name="title" type="(ref: ObjectRef) => string" required>The pane's title for an object.</Param>
<Param name="ref" type={`(params: ObjectRef["params"]) => ObjectRef`}>Makes a ref of this kind, for your own code. Optional; Jali never calls it.</Param>
<Param name="minWidth" type="number" required>The narrowest the content works at, once it adapts. Below it the pane folds into a tab; it is never squeezed past it.</Param>
<Param name="minHeight" type="number" required>The same, for height.</Param>
<Param name="comfortableWidth" type="number" default="minWidth">Where spare space takes the pane first, before any sibling grows past its own.</Param>
<Param name="maxWidth" type="number" default="unbounded">The widest the content usefully uses. Spare space past it goes to siblings that can use it; only when every sibling is at its maximum does the pane grow on, and the content keeps its measure. Leave it out for tables and charts.</Param>
<Param name="identity" type="(ref: ObjectRef) => unknown" default="every param, compared as text">What makes two refs the same object (one object, one pane). Return `undefined` for scratch space that is never matched against open panes.</Param>
<Param name="object" type="string" default="the kind">The type of object shown, shared by kinds that show the same objects differently. Two refs are the same object when their object types and identities match.</Param>
<Param name="transient" type="boolean">Stands in until the person chooses an object (the launcher): closes quietly, and gets Recent and the workspace's titles and icons.</Param>
<Param name="recordable" type="boolean | ((ref: ObjectRef) => boolean)" default="true">Whether opened objects of this kind go in Recent.</Param>
<Param name="heavy" type="boolean">Keeps its content still during a divider drag and reflows on release.</Param>
</Params>

</Entry>

<Entry name="PaneCommand" kind="type" from="@jali/core" signature={`interface PaneCommand { id: string; title: string; run: () => void; keys?: string; disabled?: string | false }`} compact>

A command a pane adds to the palette while it is focused (`setCommands`). `keys` is only a label: the content handles its own keys. `disabled` greys it out; its text is the reason.

</Entry>

<Entry name="PaneActivity" kind="type" from="@jali/core" signature={`type PaneActivity = "idle" | "loading" | "working" | "needs-you" | "error"`} compact>

What a pane reports about itself (`setActivity`), shown in its header, its tab, the shelf and the status line. On the shelf, loading reads as working.

</Entry>

<Entry name="ProfileBase" kind="type" from="@jali/core" signature={`interface ProfileBase<R extends RoleBase = RoleBase>`} compact>

A curated page about one item (a loan application), framework-free. In React, `WorkspaceProfile` adds the rail and header.

<Params title="Fields">

<Param name="home" type="string" required>The view Single opens on.</Param>
<Param name="build" type="(item: number) => Layout" required>Multiplexed's designed layout. Every role is in the tree; those not shown are hidden.</Param>
<Param name="bind" type="(item: number) => Record<string, ObjectRef>" required>What each role shows for an item. Another item swaps these in place.</Param>
<Param name="firstItem" type="number" required>The item the page opens on.</Param>
</Params>

</Entry>

<Entry name="RoleBase" kind="type" from="@jali/core" signature={`interface RoleBase { id: string; label: string; priority: "primary" | "supporting" }`} compact>

</Entry>

<Entry name="ViewMode" kind="type" from="@jali/core" signature={`type ViewMode = "single" | "multi"`} compact>

How a curated page is shown: one view at a time (Single) or side by side (Multiplexed). The person's choice, kept on their device and never in a link.

</Entry>

<Entry name="Preset" kind="type" from="@jali/core" signature={`interface Preset { id: string; label: string; build: () => Layout }`} compact>

A layout to start from or switch to ("Layout: Orders"). `build` returns a fresh layout each time.

</Entry>

<Entry name="Env" kind="type" from="@jali/core" signature={`interface Env { kinds: PaneKinds; profile: ProfileBase | null; presets: readonly Preset[]; name: string }`} compact>
