Import any of these with `import type { … } from "@jali/core"`. Functions that use them are on [@jali/core](/reference/core) and [The layout namespace](/reference/core/layout).

## The layout tree

<Entry name="Layout" kind="type" from="@jali/core" signature={`interface Layout { version: 1; root: LayoutNode; overlay?: Overlay }`} compact>

A workspace's arrangement: a tree of rows, columns and tab stacks of panes. The tree is the arrangement the person made; folds, tucks, tab choices and hidden panes are recorded in `overlay`, so they can be undone without losing a slot. This is what `?l=` holds.

<Params title="Fields">
<Param name="version" type="1" required>Always `1`.</Param>
<Param name="root" type="LayoutNode" required>The top node. A single pane is a valid root.</Param>
<Param name="overlay" type="Overlay">What the layout and the person did on top of the tree. Written by the operations; leave it out when you build a layout.</Param>
</Params>

</Entry>

<Entry name="LayoutNode" kind="type" from="@jali/core" signature={`type LayoutNode = PaneNode | StackNode | SplitNode`} compact>

One node of the tree. Every node has an `id` (unique in the layout), a `size`, and optionally `userSized` (the person dragged it) and `base` (the size a divider reset returns to).

</Entry>

<Entry name="PaneNode" kind="type" from="@jali/core" signature={`interface PaneNode { type: "pane"; id; size; ref: ObjectRef; … }`} compact>

A pane: one object, shown by its kind's component.

<Params title="Fields">
<Param name="type" type={`"pane"`} required />
<Param name="id" type="NodeId" required>Unique in the layout. In a curated page a role's pane id equals its role id.</Param>
<Param name="size" type="Size" required>Its share of its split.</Param>
<Param name="ref" type="ObjectRef" required>What it shows.</Param>
<Param name="userSized" type="boolean">The person sized it with a divider.</Param>
<Param name="base" type="Size">The size a divider reset returns to. Carried in the layout and the URL.</Param>
<Param name="linkedTo" type="NodeId">The pane it was opened from. Closing that pane drops the link.</Param>
<Param name="follows" type="boolean">It shows the object selected in `linkedTo` and changes in place when the selection moves. At most one per source and kind.</Param>
<Param name="pinned" type="boolean">Kept by the person: never reused for another object, never following, the last to fold.</Param>
<Param name="born" type="number">Its age, rising with each open; older panes fold first when over the cap. Panes without one come before new ones.</Param>
<Param name="role" type="string">The view of a curated page it fills ("borrower"). Panes without a role were opened by the person.</Param>
<Param name="priority" type={`"primary" | "supporting"`}>Supporting panes give way first when room runs out; a primary pane never folds while another can.</Param>
</Params>

</Entry>

<Entry name="SplitNode" kind="type" from="@jali/core" signature={`interface SplitNode { type: "row" | "column"; id; size; children: LayoutNode[] }`} compact>

Children side by side (`"row"`) or one above another (`"column"`), sharing the space by their sizes. Splits nobody sized share by the panes' comfortable and maximum widths; once the person sizes a child, the split keeps its proportions exactly.

</Entry>

<Entry name="StackNode" kind="type" from="@jali/core" signature={`interface StackNode { type: "stack"; id; size; children: PaneNode[]; active: NodeId; origin?: "user" }`} compact>

A tab group the person made (by merging, a centre drop or a new tab). Groups made by folding are not in the tree; they exist in `overlay`. `active` is the shown tab; `origin` is optional (`"user"` when set); leave it out in hand-written layouts.

</Entry>

<Entry name="Size" kind="type" from="@jali/core" signature={`type Size = { px: number } | { weight: number }`} compact>

A share of a split (`weight`, relative to the siblings) or a fixed length in pixels. Divider drags store weights, scaled so the ones a drag sets average 1.

</Entry>

<Entry name="NodeId" kind="type" from="@jali/core" signature={`type NodeId = string`} compact>

A node's id.

</Entry>

<Entry name="ObjectRef" kind="type" from="@jali/core" signature={`interface ObjectRef { kind: string; params: Record<string, string | number> }`} compact>

What a pane shows: a kind and the params that name the object (`{ kind: "order", params: { id: 1041 } }`). Params must be strings or finite numbers.

</Entry>

<Entry name="Axis" kind="type" from="@jali/core" signature={`type Axis = "row" | "column"`} compact>

The direction of a split.

</Entry>

<Entry name="Edge" kind="type" from="@jali/core" signature={`type Edge = "left" | "right" | "top" | "bottom"`} compact>

A side of a pane: where to open or drop. In actions and commands it is a side of the screen, in either reading direction. The layout operations (`layout.drop`, `layout.open`, `layout.split`) take a side in the tree instead: `"left"` is before, `"right"` after, which right to left is the other side of the screen.

</Entry>

<Entry name="Direction" kind="type" from="@jali/core" signature={`type Direction = "ltr" | "rtl"`} compact>

The reading direction a workspace lays its panes out in (`jali.get().dir`, `createJali({ dir })`). Right to left, a row's first child is at the right: the same tree, mirrored on screen.

</Entry>

<Entry name="Overlay" kind="type" from="@jali/core" signature={`interface Overlay { tucks; folds; shown; hidden? }`} compact>

What sits on top of the tree. Written by the operations; read it, don't write it.

<Params title="Fields">
<Param name="tucks" type="{ pane: NodeId; home: NodeId; seq: number }[]" required>Panes tucked into another pane (their home), in order.</Param>
<Param name="folds" type="NodeId[]" required>Slots folded for room, in order. The ids are opaque.</Param>
<Param name="shown" type="Record<NodeId, NodeId>" required>The chosen tab of each folded or tucked group, keyed by the group's home pane.</Param>
<Param name="hidden" type="NodeId[]">Panes taken off screen with no tab and no slot (a curated page's views in the tabs).</Param>
</Params>

</Entry>

<Entry name="ViewState" kind="type" from="@jali/core" signature={`interface ViewState { focused?: NodeId; zoomed?: NodeId; peek?: ObjectRef; focusHistory: NodeId[] }`} compact>

What the person is looking at, apart from the layout.

<Params title="Fields">
<Param name="focused" type="NodeId">The pane with workspace focus (the accent edge).</Param>
<Param name="zoomed" type="NodeId">The maximised pane. In the URL as `zoom`.</Param>
<Param name="peek" type="ObjectRef">What the peek sheet shows. In the URL as `peek`.</Param>
<Param name="focusHistory" type="NodeId[]" required>Panes most recently focused first.</Param>
</Params>

</Entry>

<Entry name="PaneKind" kind="type" from="@jali/core" signature={`interface PaneKind { kind; title(ref); minWidth; minHeight; comfortableWidth?; maxWidth? }`} compact>

The part of a kind the layout operations read, from `kinds.registry()`. The sizes are explained under <Ref to="PaneKindBase" />.

</Entry>

<Entry name="KindRegistry" kind="type" from="@jali/core" signature={`type KindRegistry = Record<string, PaneKind>`} compact>

Kinds by name, as the layout operations take them (`kinds.registry()`).

</Entry>

<Entry name="LayoutContext" kind="type" from="@jali/core" signature={`interface LayoutContext { fit: FitOptions; paneCap: number; dir?: Direction }`} compact>

Everything a layout operation needs besides the layout: `jali.ctx()`. `paneCap` is the most panes on screen before the oldest folds (the `paneCap` setting). `dir: "rtl"` mirrors the rects `resolve` returns, so they stay screen coordinates; the tree and the fit are the same.

</Entry>

<Entry name="FitOptions" kind="type" from="@jali/core" signature={`interface FitOptions { width: number; height: number; gap: number; kinds: KindRegistry }`} compact>

The room: the workspace's inner size in pixels, the gap between panes (6 in a workspace), and the kinds.

</Entry>

<Entry name="Rect" kind="type" from="@jali/core" signature={`interface Rect { x: number; y: number; width: number; height: number }`} compact>

A box in pixels, relative to the workspace's inner area.

</Entry>

<Entry name="ResolvedLayout" kind="type" from="@jali/core" signature={`interface ResolvedLayout { panes: PaneBox[]; dividers: DividerBox[]; stacks; shelf }`} compact>

What `layout.resolve` returns: `panes` and `dividers` with their rects; `stacks`, the groups made by folding and tucking (`{ id, kind: "fold" | "tuck", homeId, paneIds }`); and `shelf`, every pane behind a tab with why (`{ paneId, homeId, stackId, reason: "tucked" | "folded" | "tab" }`).

</Entry>

<Entry name="PaneBox" kind="type" from="@jali/core" signature={`interface PaneBox { id: NodeId; rect: Rect; stackId?: NodeId; hidden?: "tab" | "zoom" | "off" }`} compact>

A pane's place. `hidden`: behind another tab, behind a maximised pane, or `"off"` (hidden by the overlay, with an empty rect).

</Entry>

<Entry name="DividerBox" kind="type" from="@jali/core" signature={`interface DividerBox {\n  parentId: NodeId; index: number; axis: Axis; rect: Rect;\n  min: number; max: number; value: number;\n  neighbours?: [NodeId[], NodeId[]];\n}`} compact>

A divider between child `index` and `index + 1` of split `parentId`. `value` is the first side's length now; `min` and `max` are how far a drag can take it; `neighbours` are the panes on each side.

</Entry>

<Entry name="ResolvedStack" kind="type" from="@jali/core" signature={`interface ResolvedStack { id: NodeId; kind: "fold" | "tuck"; homeId: NodeId; paneIds: NodeId[] }`} compact>

A tab group the fit made, not one in the tree: panes folded into a neighbour (`"fold"`) or tucked into their home (`"tuck"`). `homeId` is the pane whose slot holds them.

</Entry>

<Entry name="ShelfEntry" kind="type" from="@jali/core" signature={`interface ShelfEntry { paneId: NodeId; homeId: NodeId; stackId: NodeId; reason: "tucked" | "folded" | "tab" }`} compact>

A pane that is not on screen, listed on the shelf: tucked, folded by the fit, or a background tab of a tucked or folded group. `homeId` is where it shows when put back.

</Entry>

<Entry name="UndoEntry" kind="type" from="@jali/core" signature={`interface UndoEntry {\n  kind: "close" | "closeOthers" | "tuck";\n  before: { layout: Layout; view: ViewState };\n  tucked?: NodeId;\n}`} compact>

One step of undo (`state.undoStack`): what was done and the layout and view before it. `tucked` names the pane a tuck moved.

</Entry>

</Entry>

The options of <Ref to="pane" page="/reference/core" />.

</Entry>

<Entry name="TabsOptions" kind="type" from="@jali/core" signature={`interface TabsOptions extends SizeOptions { active?: NodeId }`} compact>

</Entry>

## Kinds and pages

<Entry name="PaneOptions" kind="type" from="@jali/core" signature={`interface PaneOptions<P = Params> { params?; title; width?; height?; … }`} compact>

What a kind says about itself, apart from how it renders. In React, `definePane(kind, options)` takes these with `Component` and `icon`.

<Params title="Fields">
<Param name="params" type="ParamTypes">How to read each param back from a link, which turns values into text: `{ id: Number }` gives the component and `title` `id: number`. Declare the params every ref of the kind has; params left out stay plain `string | number` values.</Param>
<Param name="title" type="string | ((params: P) => string)" required>The pane's title in its header, its tab and the palette.</Param>
<Param name="width" type="PaneWidth" default="{ min: 240 }">

<ChildParams label="width">
<Param name="min" type="number" default="240">The narrowest the content works at, once it adapts. Below it the pane folds into a tab; it is never squeezed past it.</Param>
<Param name="comfortable" type="number" default="min">Where spare space takes the pane first, before any sibling grows past its own.</Param>
<Param name="max" type="number" default="none">The widest the content usefully uses. Spare space past it goes to siblings that can use it; only when every sibling is at its maximum does the pane grow on, and the content keeps its measure. Leave it out for tables and charts.</Param>
</ChildParams>

</Param>
<Param name="height" type="PaneHeight" default="{ min: 160 }">`min`: the shortest the content works at.</Param>
<Param name="shows" type="string" default="the kind">The type of object shown, shared by kinds that show the same objects differently. Two panes show the same object when this and their identities match.</Param>
<Param name="identity" type="(params: P) => unknown" default="every param, compared as text">What makes two panes of this kind the same object (one object, one pane). `1` and `"1"` are the same by default.</Param>
<Param name="scratch" type="boolean">Every pane is new (a scratch note, a launcher): never matched against an open pane, and left out of Recent unless `inRecent` says otherwise.</Param>
<Param name="inRecent" type="boolean | ((params: P) => boolean)" default="true (false for scratch kinds)">Whether opened objects of this kind go in Recent.</Param>
<Param name="holdWhileResizing" type="boolean">Keep the content as it is during a divider drag and reflow once, on release: for long lists and charts.</Param>
</Params>

</Entry>

<Entry name="PaneWidth" kind="type" from="@jali/core" signature={`interface PaneWidth { min?: number; comfortable?: number; max?: number }`} compact>

A kind's widths in px; see `width` under <Ref to="PaneOptions" />.

</Entry>

<Entry name="PaneHeight" kind="type" from="@jali/core" signature={`interface PaneHeight { min?: number }`} compact>

A kind's height in px; see `height` under <Ref to="PaneOptions" />.

</Entry>

<Entry name="PaneDefinition" kind="type" from="@jali/core" signature={`type PaneDefinition<P, D> = D & { (params: P): ObjectRef; readonly kind: string }`} compact>

A defined kind, callable to make its refs. In React, `Pane<P>`.

</Entry>

<Entry name="PaneKindBase" kind="type" from="@jali/core" signature={`interface PaneKindBase extends PaneOptions { kind: string }`} compact>

</Entry>

<Entry name="Params" kind="type" from="@jali/core" signature={`type Params = Record<string, ParamValue>`} compact>

A ref's params: plain data, so they fit in a link.

</Entry>

<Entry name="ParamValue" kind="type" from="@jali/core" signature={`type ParamValue = string | number`} compact>One param's value.</Entry>

<Entry name="ParamType" kind="type" from="@jali/core" signature={`type ParamType = (value: ParamValue) => ParamValue`} compact>

How to read one param back: `Number`, `String`, or your own function.

</Entry>

<Entry name="ParamTypes" kind="type" from="@jali/core" signature={`type ParamTypes = Record<string, ParamType>`} compact>A kind's `params`.</Entry>

<Entry name="ParamsOf" kind="type" from="@jali/core" signature={`type ParamsOf<T extends ParamTypes> = { [K in keyof T]: ReturnType<T[K]> } & Params`} compact>

The params a kind's code sees: `ParamsOf<{ id: NumberConstructor }>` is `{ id: number }`, with any other params as plain values.

</Entry>

<Entry name="ProfileBase" kind="type" from="@jali/core" signature={`interface ProfileBase<R extends RoleBase = RoleBase, I extends ItemId = ItemId>`} compact>

</Entry>

<Entry name="RoleBase" kind="type" from="@jali/core" signature={`interface RoleBase { id: string; label: string; priority: "primary" | "supporting" }`} compact>

One view of a curated page. In React, `PageView` adds its icon.

</Entry>

<Entry name="ViewMode" kind="type" from="@jali/core" signature={`type ViewMode = "single" | "split"`} compact>

How a curated page is shown: one view at a time (Single) or side by side (Split view). The person's choice, kept on their device and never in a link.

<Entry name="Preset" kind="type" from="@jali/core" signature={`interface Preset { id: string; label: string; build: () => Layout }`} compact>

<Entry name="PresetOptions" kind="type" from="@jali/core" signature={`interface PresetOptions { id: string; label: string; layout: LayoutInput | (() => LayoutInput) }`} compact>

A preset, as `createJali({ presets })` takes it.

</Entry>
