React components and hooks for a workspace made with [@jali/core](/reference/core). React 18.2 or later (18 or 19) is a peer dependency; nothing else is. Jali's icons are in the package. See [Icons](#icons).

```sh
npm install @jali/core @jali/react
```

Styles: `@jali/react/styles.css` is Jali's default theme and the workspace's styles; `@jali/react/theme.css` is the theme alone; `@jali/react/tailwind.css` points the tokens at your Tailwind theme. See [Tokens](/reference/tokens).

## Start here

<Entry name="JaliRoot" kind="component" from="@jali/react" signature={`<JaliRoot jali={jali} icons? overlays? settings? settingsExtra?>{children?}</JaliRoot>`} example={appCode} exampleFile="App.tsx">

Draws a workspace: its panes, and the dialogs every workspace has (the command palette unless the workspace was made with `palette: false`, Settings, the "Add to tabs of…" chooser, "Discard unsaved changes?" and the live region). While it is mounted, it starts the workspace's keys, Back and Forward, theme and saving (<Ref to="Jali" page="/reference/core/types" />'s `start`), and stops them when it unmounts.

`<JaliRoot jali={jali} />` is a whole app. To add your own chrome, pass children and put `<JaliView />` where the panes go.

The root is a `<div data-jali>` that the workspace attaches to, so focus, drag and F6 stay inside it. The dialogs render after it, in a `<div data-jali-layer>` (styled `display: contents`), which counts as the workspace's for its keys. Mark your own chrome inside it with `data-jali-chrome` and Jali never pulls focus out of it.

Two things are yours to render. **The shelf** (tucked and folded panes as chips): put <Ref to="Shelf" /> in your status line or footer, or tucked panes have nowhere to come back from but ⌘K "Show a pane from the shelf". **Toasts**: Jali sends them through `jali.onToast` (closes and tucks come with Undo, which ⌘K ⌘Z also runs) and shows none itself; render them with your toaster in `overlays`.

<Params title="Props">
<Param name="workspace" type="Jali" required>From `createJali`.</Param>
<Param name="children" type="ReactNode" default="<JaliView />">Rendered inside the root: `<JaliView>` and your chrome.</Param>
<Param name="overlays" type="ReactNode">Rendered after the root: things that must sit outside the workspace, such as a toaster. Focus is never pulled back from outside the root.</Param>
<Param name="settings" type="boolean" default="true">`false` leaves the Settings panel out.</Param>
<Param name="icons" type="Partial<JaliIcons>">Your own icons for any of the names Jali draws (`{ close: MyClose }`); the others stay Jali's. See [Icons](#icons).</Param>
<Param name="settingsExtra" type="ReactNode">Your own settings, as `<fieldset>`s with a `<legend>`, shown at the end of the Settings panel. Store their values yourself.</Param>
<Param name="...rest" type="HTMLAttributes<HTMLDivElement>">Passed to the root `<div>` (`className`, `style`, `id`). `ref` and `data-jali` are Jali's.</Param>
</Params>

</Entry>

<Entry name="JaliView" kind="component" from="@jali/react" signature={`<JaliView />`} compact>

The panes, or the curated page while one is open. Takes no props. `<JaliRoot>` renders it when it has no children; place it yourself when you add chrome.

</Entry>

## Defining panes and pages

<Entry name="definePane" kind="function" from="@jali/react" signature={`definePane(kind: string, options: PaneOptionsReact): Pane`} example={kindsCode} exampleFile="kinds.tsx">

Defines a kind of pane: what it shows (its params), its title and sizes, and the component that renders it. Pass your kinds to `createJali({ panes })`.

The result is also how you name an object of the kind: `orderKind({ id: 1041 })` is the [ref](/get-started/key-concepts#ref) `{ kind: "order", params: { id: 1041 } }`, to open, peek, select or put in a layout. When the kind declares `params`, the call is typed: a missing required param, a wrongly typed one or one the kind doesn't declare is a type error. Params are declared with `Number`, `String`, `Boolean`, <Ref to="oneOf" page="/reference/core" /> and <Ref to="optional" page="/reference/core" />, which `@jali/react` also exports.

<Params>
<Param name="kind" type="string" required>The kind's name. Every pane of this kind carries it, and links name it.</Param>
<Param name="options" type="PaneOptionsReact" required>

Everything in <Ref to="PaneOptions" page="/reference/core/types" /> (`params`, `title`, `width`, `height`, `shows`, `identity`, `scratch`, `inRecent`, `holdWhileResizing`, `follow`), and:

<ChildParams label="view fields">
<Param name="Component" type="ComponentType<PaneProps<P>>" required>Renders the pane's content. It stays mounted while the pane is folded, tabbed, tucked or moved.</Param>
<Param name="Loading" type="ComponentType<PaneProps<P>>">Shown while `Component` suspends (for example, it reads data with `use()`). It gets the same props. Default: a quiet "Loading…". The pane's activity is `"loading"` meanwhile.</Param>
<Param name="icon" type="JaliIcon">The kind's icon in the header, tab and shelf: any component that takes `{ size, className, "aria-hidden" }`, such as Phosphor's `FileTextIcon`, which matches Jali's own. Jali passes `size` and `aria-hidden`, never a weight, so your icon set's default or its context decides it. Without one, the `defaultKind` icon (a square).</Param>
</ChildParams>

</Param>
</Params>

<Returns type="Pane<P>">The kind, callable: `(params) => ObjectRef`.</Returns>

</Entry>

<Entry name="PaneProps" kind="type" from="@jali/react" signature={`interface PaneProps<P = Params>`} example={noteCode} exampleFile="order-note.tsx">

What a kind's `Component` gets. Components below it read the same with <Ref to="usePane" />. To type a component written apart from its kind, declare the params first and pass their declaration: `const orderParams = { id: Number }`, then `PaneProps<typeof orderParams>` (`params` is `{ id: number }`). `PaneProps<{ id: number }>`, the params' own type, also works.

Keys: content first. Claim the keys you use with `event.preventDefault()` (J and K, Space, Enter, ⌘Z for your own undo, the first Esc) and let the rest bubble; single character keys must act only while your content has focus. Content that needs every key (an editor) marks itself `data-pane-keys="content"`; the workspace then takes only F6 and Shift+F6 there.

<Params title="Props">
<Param name="params" type="P" required>What the pane shows, read with the kind's `params` types. A ref missing a required param, or holding a value its type can't read, never gets here: its pane shows a message naming the param instead.</Param>
<Param name="node" type="PaneNode" required>The layout node, with the full ref (`node.ref`). In the peek sheet, a node that is not in the layout.</Param>
<Param name="paused" type="boolean" required>The pane is hidden: tabbed away, tucked, folded, or behind a maximised pane. Pause subscriptions and timers; keep state.</Param>
<Param name="focused" type="boolean" required>The pane has workspace focus.</Param>
<Param name="inPeek" type="boolean" required>Rendered in the peek sheet rather than a pane.</Param>
<Param name="openBeside" type="(ref: ObjectRef) => ActionResult" required>Open `ref` beside this pane; focus stays here. The selected item opens a following detail (kept if one already follows); another link replaces this pane's earlier plain link of the same kind. Returns what `jali.actions.openBeside` does: `pane` is the pane that shows `ref`.</Param>
<Param name="openHere" type="(ref: ObjectRef) => ActionResult" required>Show `ref` in this pane. If it is open elsewhere, that pane is focused instead. In the peek sheet, which has no pane of its own, `{ ok: false, reason: "unavailable" }`.</Param>
<Param name="peek" type="(ref: ObjectRef | null) => ActionResult" required>Open or move the peek sheet; `null` closes it.</Param>
<Param name="select" type="(ref: ObjectRef | null, options?: { inResults?: boolean }) => ActionResult" required>Report the item a list is on. An open peek from this pane follows it at once; this pane's following detail once it rests. `{ inResults: false }`: the filter no longer shows `ref`. Report the selection before opening it, so the opened pane is linked to it.</Param>
<Param name="dismiss" type="() => void" required>Close this pane quietly, with no undo toast: for the launcher.</Param>
</Params>

</Entry>

## Inside a pane

Each of these acts for the pane it is called in, from any depth inside the kind's component.

<Entry name="usePane" kind="hook" from="@jali/react" signature={`usePane<P = Params>(): PaneProps<P>`} compact>

The pane's <Ref to="PaneProps" />, for components below the kind's own: `const { params, openBeside } = usePane<{ id: number }>()`. Throws outside a pane.

<Returns type="PaneProps<P>" />

</Entry>

<Entry name="useActivity" kind="hook" from="@jali/react" signature={`useActivity(activity: PaneActivity | undefined): void`} compact>

Report what the pane is doing (`"loading"`, `"working"`, `"needs-you"`, `"error"` or `"idle"`), for its header, its tab, the shelf and the status line. `undefined` reports nothing. Reported again whenever it changes.

</Entry>

<Entry name="useUnsaved" kind="hook" from="@jali/react" signature={`useUnsaved(what: string | null | false | undefined): void`} compact>

Report unsaved work in words (`"an unsaved query"`), or a falsy value once it is saved, so `useUnsaved(dirty && "an unsaved note")` works. While a pane has some, closing it, closing others, a preset or showing another object in it asks first; a following detail keeps its object. Moving, tabbing, folding and tucking never ask. Cleared when the component unmounts.

</Entry>

<Entry name="useTitle" kind="hook" from="@jali/react" signature={`useTitle(title: string | null | undefined): void`} compact>

Name the pane from its data: `useTitle(customer.data?.name)` shows "Acme Ltd" rather than the kind's "Customer 12". While set, it replaces the kind's `title` in the header, the tab, the shelf, the palette, the switcher, announcements and `jali.model().title(id)`. In a curated page, the view's label still names the pane, and this title is shown beside it. `null` or `undefined` goes back to the kind's title.

It is cleared when the component unmounts and when the pane shows another object, then set again from the next render. It is not saved, so a reload shows the kind's title until the data loads. The peek sheet keeps the kind's title.

</Entry>

<Entry name="usePaneAttributes" kind="hook" from="@jali/react" signature={`usePaneAttributes(attributes: Record<\`data-\${string}\`, string> | null | undefined): void`} compact>

Mark the pane from its data with `data-*` attributes, so your styles can tell it apart: `usePaneAttributes({ "data-connection": "production" })` on a query pane connected to production. Jali puts them on everything that stands for the pane: its section, its tab in any strip (folded and tucked too), its shelf chip, its entry in the phone's pane switcher, the tab and shelf menus, and the peek sheet while it shows the pane's object. Jali gives them no style of its own.

Only `data-*` names are kept, and not the ones Jali's own parts use (`data-pane`, `data-tab`, `data-focused`, `data-jali-*` and the rest). `null` or `undefined` clears them. They are cleared when the component unmounts and when the pane closes or shows another object, then set again from the next render. They are not saved. The peek sheet's own content can't set them.

</Entry>

<Entry name="useCommands" kind="hook" from="@jali/react" signature={`useCommands(commands: readonly PaneCommand[]): void`} compact>

The commands this pane lists first in the palette while it is focused. Pass them on every render: they are listed again only when an id, title, keys label or disabled reason changes, and each runs the latest `run` it was given, so `run` can close over current state. Removed when the component unmounts.

</Entry>

For the workspace's launcher: what the person can choose from.

<Returns type="LauncherSources" />

</Entry>

<Entry name="LauncherSources" kind="type" from="@jali/react" signature={`interface LauncherSources {\n  recent: ObjectRef[];\n  isOpen(ref: ObjectRef): boolean;\n  titleOf(ref: ObjectRef): string;\n}`} compact>

<Entry name="usePaneState" kind="hook" from="@jali/react" signature={`usePaneState<T>(key: string, initial: T): [T, (next: T | ((prev: T) => T)) => void]`} example={paneStateCode} exampleFile="OrdersTable.tsx">

State the workspace keeps for a pane: it survives the pane being tabbed, folded, tucked or moved, and a reload (saved on this device 400 ms after it changes). It is dropped when the pane closes for good or shows another object. Use it for what a person expects back (a sort, a draft, a scroll position) and React state for the rest.

In the peek sheet there is no pane, so the state is local and goes with the sheet.

<Params>
<Param name="key" type="string" required>The value's name within the pane.</Param>
<Param name="initial" type="T" required>Used until a value is set. Read once, as with `useState`. Must be JSON.</Param>
</Params>

<Returns type="[T, (next: T | ((prev: T) => T)) => void]">The value, and a setter that takes a value or an updater. Values must be JSON.</Returns>

</Entry>

<Entry name="useActiveItemPort" kind="hook" from="@jali/react" signature={`useActiveItemPort(mapping: ActiveItemMapping): ActiveItemPort | null`} example={portCode} exampleFile="OrdersPane.tsx">

The active-item port for the pane this content is in (see <Ref to="activeItemPort" page="/reference/core" />). Re-renders when the pane's selection changes, so `itemId` reads fresh.

<Params>
<Param name="mapping" type="ActiveItemMapping" required>`toRef(itemId)` and `idOf(ref)`. The port always uses the latest render's mapping and stays the same object, so an inline object is fine.</Param>
</Params>

<Returns type="ActiveItemPort | null">`null` in the peek sheet.</Returns>

</Entry>

## Parts

`<JaliRoot>` and `<JaliView>` render these. Use them to compose your own: each must be inside a `<JaliProvider>`, and none takes props unless shown.

<Entry name="Panes" kind="component" from="@jali/react" signature={`<Panes />`} example={composeCode} exampleFile="App.tsx">

The panes: frames, dividers, drop zones, the drag chip, the peek sheet and (on a phone) the pane switcher. It is a `<section aria-label="Panes">` region, or the page's `<main>` with `createJali({ landmark: "main" })`, measures itself to set the workspace's `area`, keeps DOM focus on the focused pane, and announces panes folding or unfolding when the room changes. When even one pane's minimum doesn't fit, it shows one pane at a time. It is `position: relative` with `overflow: hidden` and no size of its own. Jali's styles make the root (`[data-jali]`) fill its box as a flex column, with the panes at `flex: 1`, so they take the room your own chrome leaves. Your own layout (a grid or flex cell) wins over those styles. If the panes still measure 0 high after they mount, a development warning in the console says so.

</Entry>

<Entry name="CuratedPage" kind="component" from="@jali/react" signature={`<CuratedPage />`} compact>

A curated page: the page's `Rail` at the left; its `Header`, the page tabs and `<Panes>` at the right. Renders only while a page is open (it reads it without checking).

</Entry>

<Entry name="PageBar" kind="component" from="@jali/react" signature={`<PageBar />`} compact>

A curated page's controls, for your top bar: the Single / Split view switch (Split view disabled for a limited viewer), in Split view the "Investigating · N opened" group with Back to the page, and Reset. Renders nothing while no page is open.

</Entry>

<Entry name="Shelf" kind="component" from="@jali/react" signature={`<Shelf />`} compact>

The panes that are tabs but not by the person's choice: tucked ones (with Put back) and folded ones, as chips grouped by home, for a status line. More than three folded panes collapse into one summary chip. Arrow keys move between chips, Enter shows one, Shift+Enter puts a tucked one back. Renders nothing when no pane is tucked or folded.

</Entry>

<Entry name="Announcer" kind="component" from="@jali/react" signature={`<Announcer />`} compact>

The one polite live region (`role="status"`) every layout change is announced in. It clears and then sets the text, so a repeat is announced again.

</Entry>

<Entry name="Palette" kind="component" from="@jali/react" signature={`<Palette />`} compact>

The command palette (⌘K or Ctrl+K), while `paletteOpen` is set. The focused pane's own commands come first, then every workspace command with its group and keys; refused ones are greyed. Choosing one closes the palette and runs it once focus is back.

</Entry>

<Entry name="SettingsPanel" kind="component" from="@jali/react" signature={`<SettingsPanel>{extra?}</SettingsPanel>`} compact>

The Settings dialog, while `settingsOpen` is set: theme, centre drop, pane cap (2 to 16), a curated page's opened-pane marking and viewer, every key binding from the workspace's keymap, then its children (your own fieldsets; `<JaliRoot settingsExtra>`). Changes go through `actions.changeSettings` and are saved on this device.

</Entry>

<Entry name="Chooser" kind="component" from="@jali/react" signature={`<Chooser />`} compact>

"Add to tabs of…" (the `pane.merge` command): pick a pane or tab group on screen by title, and the focused pane joins it. Renders while `chooser` is set.

</Entry>

<Entry name="ConfirmDiscard" kind="component" from="@jali/react" signature={`<ConfirmDiscard />`} compact>

"Discard unsaved changes?", while a change that would lose unsaved work is held (`confirm`). Lists each pane and its work. Keep editing is the default (focused, Esc and a click outside); Discard makes the held change as it was asked for.

</Entry>

<Entry name="KindIcon" kind="component" from="@jali/react" signature={`<KindIcon kind={kind} size={16} />`} example={iconCode} exampleFile="OpenPanes.tsx">

A kind's icon at `size`, `aria-hidden`; the `defaultKind` icon (a square unless you replaced it) for an unknown kind or one without an icon.

## Icons

Jali draws its own chrome icons from a map of names (`JaliIcons`). Its defaults are in the package (Phosphor's regular weight, copied, so you install no icon library), and `<JaliRoot icons>` replaces any of them. A kind's icon is the kind's own (`definePane({ icon })`). The host's buttons (your top bar, ⌘K, settings, a switcher) are yours and use your icons already. See [Your own icons](/guides/theming#your-own-icons).

```ts
import { JaliRoot } from "@jali/react"; // Jali's icons; icons={...} replaces any of them
import { defaultIcons } from "@jali/react/icons"; // Jali's full set, to spread under your own
```

<Entry name="JaliIcons" kind="type" from="@jali/react" signature={`type JaliIcons = Record<JaliIconName, JaliIcon>`}>

One icon per name Jali draws. `<JaliRoot icons>` takes any part of it; type your own set as `JaliIcons` to have the types check it names every icon.

<Member name="icons.restore" signature="restore: JaliIcon">Restore a maximised pane. Default: Phosphor's `ArrowsInSimple`.</Member>
<Member name="icons.fullScreen" signature="fullScreen: JaliIcon">Put a pane on the whole screen. Default: Phosphor's `CornersOut`.</Member>
<Member name="icons.exitFullScreen" signature="exitFullScreen: JaliIcon">Leave full screen. Default: Phosphor's `CornersIn`.</Member>

## Experimental

Prototypes, to try and give feedback on. Their names start `unstable_`, and their shape may change in any release.

<Entry name="unstable_popOut" kind="function" from="@jali/react" signature={`unstable_popOut(jali: Jali, pane?: string, size?: { width: number; height: number }): Promise<boolean>`} compact>

Off until the workspace allows it: `createJali({ allow: { popOut: true } })`. Opens a pane (default: the focused one) in a floating window that stays on top of every other window, even while the person is in another tab or app, as a video call's does. It uses the browser's Document Picture-in-Picture, in Chrome and Edge on desktop; resolves `false` elsewhere. Call it from a click or a key, since the browser asks for the person's gesture. Where it's allowed, people also find Pop out in a tab's menu and a pane header's (right-click). The window matches the page's browser zoom.

The pane keeps its place in the layout, which says "Popped out into its own window" with a Bring back button. Its content renders in the window with the page's styles and theme, and keeps Jali's context, so its hooks, data and actions work. Closing the window, Bring back, or closing the pane puts it back. One pane at a time.

Known limits: the content remounts as it moves, so its own `useState` starts again (`usePaneState` and your data cache carry over); Jali's keys don't work inside the window yet; and the window closes when the page that opened it navigates away.

</Entry>

<Entry name="unstable_bringBack" kind="function" from="@jali/react" signature={`unstable_bringBack(): void`} compact>

Puts the popped-out pane back in its place and closes its window.

</Entry>

<Entry name="unstable_canPopOut" kind="function" from="@jali/react" signature={`unstable_canPopOut(): boolean`} compact>

Whether this browser can pop a pane out: Document Picture-in-Picture on a secure page. Use it to offer Pop out only where it works.

</Entry>
