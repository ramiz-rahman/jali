The framework-free part of Jali: the workspace, the layouts it shows, the address and storage ports, commands and keys. Render it with [@jali/react](/reference/react). Types have their own page, [@jali/core types](/reference/core/types); the pure layout operations are on [The layout namespace](/reference/core/layout).

```sh
npm install @jali/core
```

Framework adapters import `@jali/core/adapter`, which exports everything inside the package. Apps need only what is on this page.

## The workspace

<Entry name="createWorkspace" kind="function" from="@jali/core" signature={`createWorkspace(options: WorkspaceOptions): Workspace`} example={createCode} exampleFile="workspace.ts">

Makes one workspace, ready to render: its state, the model derived from it, its actions and its keymap. Each workspace has its own; nothing is shared between two on one page.

Before it returns, it reads the address (a layout link opens as it is, a curated page link opens the page, a link that can't be read opens the starting layout with an error toast), adds what is on screen to Recent, fits the layout to the room and focuses the first pane. A page-only app (a `page` with no `layout` and no `presets`) starts with its page open on `firstItem`, and "Open Workspace" is refused. It throws ``Jali: give the workspace a `layout`, `presets` or a `page` to start from`` when it has none of them.

Its listeners (keys, Back and Forward, theme and saving) start with `workspace.start()`, which `<Jali>` calls while it is mounted.

<Params title="Parameters">
<Param name="options" type="WorkspaceOptions" required>

<ChildParams>
<Param name="panes" type="readonly PaneKindBase[]" required>The kinds of pane it can show, from `definePane`. A layout can only show refs of these kinds.</Param>
<Param name="layout" type="LayoutInput">The layout it opens on: a builder's result (`row(...)`), a single ref, or a whole `Layout`. Give this or `presets`.</Param>
<Param name="presets" type="readonly PresetOptions[]" default="[]">Layouts to start from, in menu order, each `{ id, label, layout }`. Each gets a `layout.preset.<id>` command, titled "Layout: label", and "Reset layout" rebuilds the one in use. `layout` may be a function, to build a fresh one each time.</Param>
<Param name="preset" type="string" default="the first preset">The preset it opens on when no link says otherwise. An id that is not in `presets` also gives the first.</Param>
<Param name="launcher" type="PaneKindBase">What Split and "New tab here" open until the person chooses what to show. It closes quietly and its component reads `useLauncher()`. Without one, those commands and the tab strip's "+" are not offered.</Param>
<Param name="page" type="Page | null" default="null">A curated page this workspace can show, from `definePage`.</Param>
<Param name="name" type="string" default={`"Workspace"`}>The free workspace's name, in command titles such as "Open Workspace".</Param>
<Param name="url" type="boolean | UrlSyncOptions" default="true in a browser">

The address.

<Values>
<Value name="true">The layout lives in the address bar: a link reopens it, and Back and Forward step through it.</Value>
<Value name="options">The same, configured: `{ location, prefix, sizes }`. See <Ref to="UrlSyncOptions" page="/reference/core/types" />.</Value>
<Value name="false">The address is left alone.</Value>
</Values>

</Param>
<Param name="storage" type="string | StoragePort" default={`its id in a browser, memory elsewhere`}>What this person keeps on this device: settings, pane state, a curated page's mode and layout, dragged sizes. A string is a `localStorage` prefix; or pass a port, such as `memoryStorage()`. The default prefix is the workspace's `id` (`"jali"`), so two workspaces with their own ids keep their own.</Param>
<Param name="id" type="string" default={`"jali"`}>Prefix for DOM ids (`jali-pane-orders`). Give each workspace on one page its own.</Param>
<Param name="keys" type={`"page" | "workspace"`} default={`"page"`}>`"page"`: every key on the page. `"workspace"`: only keys pressed inside it or in its dialogs (the palette, settings and the chooser render outside its root, so a ⌘K chord finishes there), and keys with nothing focused while it was the last one used. Use `"workspace"` for two on one page.</Param>
<Param name="pageTheme" type="boolean" default="true">Set `data-theme` on `<html>` from the person's theme setting. `false` when the workspace sits in a page that has its own theme.</Param>
<Param name="commands" type="readonly Command[]">Your own commands. They are listed in ⌘K after Jali's, and `keymap` can bind them like any other (`{ "orders.refresh": "Mod+K Mod+U" }`). If an id repeats one of Jali's, Jali's wins.</Param>
<Param name="keymap" type="KeymapOverrides">Rebind or unbind commands: `{ "pane.zoom": "Mod+K Mod+Enter", "pane.close": null }`. A binding is refused (and reported) when it can't be parsed, is a single character key with no Mod, Ctrl or Alt (those belong to the content), or has more than two steps.</Param>
<Param name="keymapOptions" type="KeymapOptions">`platform` (`"mac"` or `"other"`, for tests and the server) and `onInvalid(id, binding, reason)` (default `console.warn`).</Param>
<Param name="size" type="{ width: number; height: number }">A fixed size instead of the window's, for tests and server rendering. `<Jali>` measures the real one once it renders.</Param>
<Param name="moveFocus" type="boolean" default="true">`false` leaves DOM focus alone: for tests and a workspace that is never shown.</Param>
<Param name="onUnstable" type="(op: string, before: string, after: string) => void" default="console.error in development">Called when a focus or swap action moved a pane on screen, which it never should.</Param>
</ChildParams>
</Param>
</Params>

<Returns type="Workspace">The workspace. Its members are listed under <Ref to="Workspace" page="/reference/core/types" />; the ones you use most are `actions`, `get()`, `subscribe()`, `model()` and `start()`.</Returns>

</Entry>

<Entry name="actions" kind="namespace" from="@jali/core (workspace.actions)" note="A member of the workspace, not an import" signature={`workspace.actions.openBeside(source: NodeId, ref: ObjectRef): NodeId | undefined`} example={readCode} exampleFile="actions.ts">

Every workspace action, bound to its workspace: each reads the current state, commits what it decides (layout, focus, address, announcement, toast) and returns the pane it opened or acted on, when there is one.

An action that would remove or replace a pane with unsaved work is held instead, and "Discard unsaved changes?" opens (`WorkspaceState.confirm`). A following detail with unsaved work keeps its object and says so. Every action is listed under <Ref to="Actions" page="/reference/core/types" />.

</Entry>

## Layouts

<Entry name="row" kind="function" from="@jali/core" signature={`row(options?: SizeOptions, ...children: (Draft | ObjectRef)[]): Draft`} example={builderCode} exampleFile="layouts.ts">

Children side by side. A child is a ref (a pane showing it), a `pane(ref, options)`, or another `row`, `column` or `tabs`. Options come first when there are any: `row({ weight: 2 }, a, b)`.

Nodes without an `id` are named after what they hold: `"row"`, `"column"`, `"tabs"`, or the pane's kind, then `"order-2"` and so on. Give an `id` to a pane another one links to, or that your code names.

<Params>
<Param name="options" type="SizeOptions">`id`; `weight` (its share of the parent, default 1) or `px` (a fixed length).</Param>
<Param name="children" type="(Draft | ObjectRef)[]" required />
</Params>

<Returns type="Draft">For `createWorkspace({ layout })`, a preset's `layout`, or <Ref to="toLayout" />.</Returns>

</Entry>

<Entry name="column" kind="function" from="@jali/core" signature={`column(options?: SizeOptions, ...children: (Draft | ObjectRef)[]): Draft`} compact>

Children one above the other. Otherwise the same as <Ref to="row" />.

</Entry>

<Entry name="tabs" kind="function" from="@jali/core" signature={`tabs(options?: TabsOptions, ...panes: (PaneDraft | ObjectRef)[]): Draft`} compact>

Panes as tabs in one place: a stack the person made. `options.active` names the tab shown (default: the first); `id`, `weight` and `px` as for <Ref to="row" />.

</Entry>

<Entry name="pane" kind="function" from="@jali/core" signature={`pane(ref: ObjectRef, options?: PaneNodeOptions): PaneDraft`} compact>

A pane showing `ref`, with options. A bare ref in a `row` is the same as `pane(ref)`.

<Params>
<Param name="ref" type="ObjectRef" required>What it shows: `orderKind({ id: 1 })`.</Param>
<Param name="options" type="PaneNodeOptions">

<ChildParams label="options">
<Param name="id" type="string">Its node id. Default: its kind's name, then `name-2`, ….</Param>
<Param name="weight" type="number" default="1">Its share of the parent.</Param>
<Param name="px" type="number">A fixed length along the parent's axis instead.</Param>
<Param name="linkedTo" type="string">The pane it was opened from. Closing that pane drops the link.</Param>
<Param name="follows" type="boolean">With `linkedTo`: it shows whatever is selected in that pane, and moves with the selection.</Param>
<Param name="pinned" type="boolean">Kept by the person: never reused for another object, never following, the last to fold.</Param>
<Param name="role" type="string">The place it fills in a curated page's designed layout (the view's id).</Param>
<Param name="priority" type={`"primary" | "supporting"`}>Supporting panes give way first when room runs out.</Param>
<Param name="hidden" type="boolean">Off screen at the start, with no slot or tab; showing it brings it back.</Param>
</ChildParams>

</Param>
</Params>

<Returns type="PaneDraft" />

</Entry>

<Entry name="toLayout" kind="function" from="@jali/core" signature={`toLayout(input: LayoutInput): Layout`} compact>

The plain layout tree a builder's result stands for, with an id on every node: what the address carries and the layout namespace works on. A whole `Layout` comes back as it is; a single ref becomes a one-pane layout. You rarely need it: everything that takes a layout takes a builder's result.

<Returns type="Layout" />

</Entry>

<Entry name="sameRef" kind="function" from="@jali/core" signature={`sameRef(a: ObjectRef | undefined, b: ObjectRef | undefined): boolean`} example={sameRefCode} exampleFile="same-ref.ts">

Whether two refs are exactly the same: the same kind and the same params, compared with `===`. `1` and `"1"` differ here; to ask whether two refs show the same object, use `kinds.sameObject`.

<Params>
<Param name="a" type="ObjectRef | undefined" required />
<Param name="b" type="ObjectRef | undefined" required />
</Params>

<Returns type="boolean">`false` when either is `undefined`.</Returns>

</Entry>

## The address and storage

`createWorkspace` makes these for you from its `url` and `storage` options. Pass one yourself for a router, a test or a workspace that must not touch the page.

<Entry name="browserLocation" kind="function" from="@jali/core" signature={`browserLocation(win?: Window): LocationPort`} compact>

The address as the browser's history: `navigate` calls `pushState` or `replaceState` with the same path and hash (and does nothing when the address would not change), and `subscribe` listens to `popstate`.

<Params>
<Param name="win" type="Window" default="window">The window whose history to use.</Param>
</Params>

<Returns type="LocationPort" />

</Entry>

<Entry name="memoryLocation" kind="function" from="@jali/core" signature={`memoryLocation(initial?: string): LocationPort & { entries: string[]; visit(search: string): void }`} example={createCode} exampleFile="workspace.ts" exampleHighlight="21-31">

An address that lives in memory: for tests, server rendering, and a workspace in a dialog that must not touch the page's address.

<Params>
<Param name="initial" type="string" default={`""`}>The first search string.</Param>
</Params>

<Returns type="LocationPort & { entries: string[]; visit(search: string): void }">`entries` is the history, newest last; `href()` is `memory:` plus the search. `visit(search)` is navigation the workspace did not make (Back, a router link): it adds an entry and calls every subscriber. `navigate` does not call subscribers.</Returns>

</Entry>

<Entry name="browserStorage" kind="function" from="@jali/core" signature={`browserStorage(prefix: string): StoragePort`} compact>

`localStorage` under `prefix` (keys are `prefix:key`). Reads and writes never throw: in private mode or with storage blocked, nothing is saved and reads give `null`.

<Params>
<Param name="prefix" type="string" required>The key prefix. `createWorkspace({ storage: "orders" })` makes one for you.</Param>
</Params>

<Returns type="StoragePort" />

</Entry>

<Entry name="memoryStorage" kind="function" from="@jali/core" signature={`memoryStorage(initial?: Record<string, string>): StoragePort`} compact>

Storage in a `Map`, for tests, server rendering and embedded workspaces.

<Params>
<Param name="initial" type="Record<string, string>" default="{}">Keys to start with (`settings`, `pane-state`, …).</Param>
</Params>

<Returns type="StoragePort" />

</Entry>

## Commands and keys

<Entry name="commandsOf" kind="function" from="@jali/core" signature={`commandsOf(workspace: Workspace): readonly Command[]`} example={commandsCode} exampleFile="toolbar.ts">

Every command the workspace has, in palette order: the fixed set, one per preset, and titles in the workspace's own words (its name, its page's name and viewers). The same array for the same workspace. Every id is on the [Commands](/reference/commands) page.

<Params>
<Param name="workspace" type="Workspace" required>The workspace (only its `env` is read).</Param>
</Params>

<Returns type="readonly Command[]">Each with `id`, `title`, `group`, an optional `check` that returns a refusal when it can't run now, and `run`.</Returns>

</Entry>

<Entry name="runCommand" kind="function" from="@jali/core" signature={`runCommand(workspace: Workspace, id: string): boolean`} compact>

Runs a command by id if its check passes. A refusal is not announced here (the keyboard and the palette do that).

<Params>
<Param name="workspace" type="Workspace" required />
<Param name="id" type="string" required>A command id, such as `"pane.zoom"`.</Param>
</Params>

<Returns type="boolean">Whether it ran: `false` for an unknown id or a refused check.</Returns>

</Entry>

<Entry name="copyLink" kind="function" from="@jali/core" signature={`copyLink(workspace: Workspace): void`} compact>

Writes `workspace.href()` to the clipboard and announces "Link copied", or "Couldn't copy the link" when the browser refuses. Where `navigator.clipboard` is missing it does nothing. The `layout.copy_link` command runs it.

<Params>
<Param name="workspace" type="Workspace" required />
</Params>

<Returns type="void" />

</Entry>

<Entry name="DEFAULT_KEYMAP" kind="constant" from="@jali/core" signature={`const DEFAULT_KEYMAP: { readonly "palette.toggle": readonly ["Mod+K"]; … }`} example={keymapCode} exampleFile="keymap.ts" exampleHighlight="8">

The default bindings: command id to one or more binding strings. `Mod` is ⌘ on a Mac and Ctrl elsewhere. Each id and its keys, printed for both platforms, are on the [Commands](/reference/commands) page.

The defaults keep to three rules:

- single character keys belong to the focused content;
- no keys the browser keeps for itself (⌘W, ⌘T, Ctrl+Tab and the like), no Ctrl+Alt, and no ⌘ or Ctrl with a digit;
- one prefix, ⌘K or Ctrl+K, which opens the palette and starts a two-step chord whose second step keeps Mod held.

</Entry>

<Entry name="formatKeys" kind="function" from="@jali/core" signature={`formatKeys(seq: KeySequence, platform?: Platform): string`} example={formatCode} exampleFile="format.ts">

A key sequence as people read it: "⌘K ⌘M" on a Mac, "Ctrl+K Ctrl+M" elsewhere. Sequences come from `keymap.sequences(id)`.

<Params>
<Param name="seq" type="readonly Chord[]" required>One binding: a chord, or a prefix chord and a second chord.</Param>
<Param name="platform" type="Platform" default="this platform" />
</Params>

<Returns type="string" />

</Entry>

<Entry name="keyHint" kind="function" from="@jali/core" signature={`keyHint(text: string, platform?: Platform): string`} compact>

A binding string printed for the platform: `keyHint("Alt+Enter")` is "⌥↵" on a Mac and "Alt+Enter" elsewhere. For keys a pane handles itself, which are not in the keymap. Throws on a key or modifier it doesn't know.

<Params>
<Param name="text" type="string" required>A binding such as `"Mod+K Mod+M"`.</Param>
<Param name="platform" type="Platform" default="this platform" />
</Params>

<Returns type="string" />

</Entry>

## Lists and their detail

<Entry name="activeItemPort" kind="function" from="@jali/core" signature={`activeItemPort(workspace: Workspace, pane: NodeId, mapping: ActiveItemMapping): ActiveItemPort`} example={activeCode} exampleFile="active-item.ts">

Lets a list inside a pane keep its current item through the workspace, so the pane's following detail follows it, Space shows it and an open peek steps with it. The shape matches Chakni's Quick Look port, so a Chakni collection plugs in with no dependency either way. In React, `useActiveItemPort`.

`write(id, "step")` reports the selection (the detail follows once it rests, 150 ms). `"open"` also shows the item: in the following detail when it is on screen, else the peek sheet. `"close"` closes the peek only if this pane opened it; the selection stays. `itemId` reads the pane's selection through `idOf`.

<Params>
<Param name="workspace" type="Workspace" required />
<Param name="pane" type="NodeId" required>The pane the list is in.</Param>
<Param name="mapping" type="ActiveItemMapping" required>

<ChildParams label="mapping">
<Param name="toRef" type="(itemId: string) => ObjectRef" required>The object an item id shows.</Param>
<Param name="idOf" type="(ref: ObjectRef) => string | null" required>The item id of an object, or `null` when it is not one of this list's items.</Param>
</ChildParams>

</Param>
</Params>

<Returns type="ActiveItemPort">`{ itemId, write(itemId, action) }`; `write` always returns `{ status: "accepted" }`.</Returns>

</Entry>

## Geometry

<Entry name="GAP" kind="constant" from="@jali/core" signature={`const GAP: number`} compact>

The gap between panes and the workspace's inset, in pixels (6). For measuring a workspace from outside: its usable area is its element's size minus `GAP * 2`.

</Entry>

## The layout namespace

<Entry name="layout" kind="namespace" from="@jali/core" signature={`import { layout } from "@jali/core";`} example={layoutCode} exampleFile="layout.ts">

The pure layout tree API: every operation takes a layout (and usually the view and a `LayoutContext`) and returns a new one; nothing is changed in place. The workspace's actions are built on it. To write a layout, use the builders above; these are for working on one. Use it to build or test layouts, or to work out what an action would do. Each member is on [The layout namespace](/reference/core/layout).

</Entry>
