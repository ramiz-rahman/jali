The framework-free part of Jali: the layout tree and its operations, the workspace store, start-up, the address and storage ports, commands and keys. Render it with [@jali/react](/reference/react). Types have their own page, [@jali/core types](/reference/core/types); the pure layout operations are on [The layout namespace](/reference/core/layout).

```sh
npm install @jali/core
```

## The store

<Entry name="createUiStore" kind="function" from="@jali/core" signature={`createUiStore(deps: UiStoreDeps): UiStore`} example={storeCode} exampleFile="store.ts">

Makes one workspace: its state, the model derived from it, its actions and its keymap. Each workspace has its own store; nothing is shared between two stores on one page.

It throws ``createUiStore: give `presets` or an `initial.layout` to start from`` when it has neither. The first state is the start preset's layout (or `initial.layout`), the settings and pane state saved in `storage`, and no focus. Call <Ref to="boot" /> before the first render to bring in the address and fit the layout.

<Params title="Parameters">
<Param name="deps" type="UiStoreDeps" required>

What the workspace is made of, and where its effects go.

<ChildParams>
<Param name="kinds" type="PaneKinds" required>This workspace's pane kinds, from <Ref to="createPaneKinds" />. A layout can only show refs of these kinds.</Param>
<Param name="presets" type="readonly Preset[]" default="[]">Layouts to start from, in menu order. Each gets a `layout.preset.<id>` command, titled "Layout: label".</Param>
<Param name="preset" type="string" default="the first preset">The preset the workspace opens on when no link or saved state says otherwise. An id that is not in `presets` also gives the first.</Param>
<Param name="initial" type="Partial<UiState>">State laid over the defaults, last, so it wins over saved settings and pane state too. A workspace without presets passes `initial.layout`.</Param>
<Param name="profile" type="ProfileBase | null" default="null">The curated page this workspace can show. In React, a `WorkspaceProfile`.</Param>
<Param name="name" type="string" default={`"Workspace"`}>The free workspace's name, used in command titles such as "Open Workspace".</Param>
<Param name="url" type="UrlWriter">Where the workspace writes its address: usually <Ref to="createUrlSync" />, which `boot` and `startUi` then also read from. Without it the address is left alone.</Param>
<Param name="storage" type="StoragePort" default={`browserStorage("jali")`}>What this person keeps on this device: settings, pane state, a curated page's mode and layout.</Param>
<Param name="id" type="string" default={`"jali"`}>Prefix for this workspace's DOM ids (`jali-pane-orders`). Give each workspace on one page its own.</Param>
<Param name="focusPane" type="((scope: WorkspaceDom, id: NodeId) => void) | null" default="focusPane, or null without a document">Moves DOM focus into a pane after the next paint. `null` leaves DOM focus alone, for tests and workspaces that are never shown.</Param>
<Param name="keymap" type="KeymapOverrides">Rebind or unbind commands: `{ "pane.zoom": "Mod+K Mod+Enter", "pane.close": null }`. See <Ref to="createKeymap" />.</Param>
<Param name="keymapOptions" type="KeymapOptions">The keymap's platform, and how refused bindings are reported.</Param>
<Param name="unstable" type="(op: string, before: string, after: string) => void" default="console.error in development">Called when a focus or swap action moved a pane on screen, which it never should. Outside development nothing is checked.</Param>
</ChildParams>
</Param>
</Params>

<Returns type="UiStore">The store. Its members are listed under <Ref to="UiStore" page="/reference/core/types" />; the ones you use most are `get()`, `set()`, `subscribe()`, `model()` and `actions`.</Returns>

</Entry>

<Entry name="boot" kind="function" from="@jali/core" signature={`boot(store: UiStore, url?: UrlSync): void`} example={bootCode} exampleFile="main.tsx" exampleHighlight="7">

Puts the first state in place before the first render, so the first paint is the layout the address holds.

In order, it:

1. reads the address. A layout link arrives as it is, and a curated page link opens the page. A link that can't be read opens the current preset, keeps a copy of the code in storage, replaces the address, shows an error toast and announces it;
2. adds what is on screen to Recent;
3. fits the layout to the current area;
4. focuses the first pane when nothing is focused;
5. replaces the address with the result.

<Params>
<Param name="store" type="UiStore" required>The workspace to start.</Param>
<Param name="url" type="UrlSync" default="store.url, when it can read">The address to read. Defaults to the store's own `url` when it is a <Ref to="createUrlSync" /> (it has `read`); with neither, `boot` only fits and focuses.</Param>
</Params>

<Returns type="void" />

</Entry>

<Entry name="startUi" kind="function" from="@jali/core" signature={`startUi(store: UiStore, url?: UrlSync): () => void`} example={bootCode} exampleFile="main.tsx" exampleHighlight="8">

Installs the listeners a workspace needs for the life of the page, and returns a function that removes them.

- Writes `--gap`, `--topbar-h`, `--status-h` and `--switcher-h` on `<html>` (the pane switcher on a phone reads `--switcher-h`).
- Sets `data-theme` on `<html>` to the resolved theme, and again when the setting or the system preference changes.
- Saves settings when they change, pane state 400 ms after it last changed, and a curated page's mode and Multiplexed layout (without opened panes).
- Asks the browser to confirm leaving the page while any pane has unsaved work (`beforeunload`).
- Installs the keyboard with <Ref to="installKeyboard" /> on `window`, with no root: it takes keys from the whole page.
- Applies Back and Forward from `url` and announces "Layout changed by browser history".

<Params>
<Param name="store" type="UiStore" required>The workspace.</Param>
<Param name="url" type="UrlSync" default="store.url, when it can read">The address whose Back and Forward to follow.</Param>
</Params>

<Returns type="() => void">Removes every listener and cancels a pending pane state save. For tests and hot reload.</Returns>

</Entry>

<Entry name="createPaneKinds" kind="function" from="@jali/core" signature={`createPaneKinds<D extends PaneKindBase = PaneKindBase>(defs?: readonly D[]): PaneKinds<D>`} example={kindsCode} exampleFile="kinds.ts">

Makes a workspace's registry of pane kinds. Each store has its own, so two workspaces, a workspace in a dialog and every test stay independent.

In React, pass kinds made with `definePaneKind`; the registry then also holds their components and icons.

<Params>
<Param name="defs" type="readonly D[]" default="[]">The kinds to start with. A later kind with the same `kind` name replaces an earlier one.</Param>
</Params>

<Returns type="PaneKinds<D>">

The registry. `register(def)` adds or replaces a kind later (late imports, hot reload) and bumps `version()`; `onChange` hears it. `registry()` is the framework-free view the layout operations read (`minWidth`, `minHeight`, `comfortableWidth`, `maxWidth`), the same object until the next registration. `title(ref)` falls back to the kind name for an unknown kind or a title that throws. `sameObject` compares object types (`object`, else the kind) and identities; a kind whose `identity` returns `undefined` is scratch space and is never the same object as anything. All members: <Ref to="PaneKinds" page="/reference/core/types" />.

</Returns>

</Entry>

<Entry name="actions" kind="namespace" from="@jali/core (store.actions)" note="A member of the store, not an import" signature={`store.actions.openBeside(source: NodeId, ref: ObjectRef): NodeId | undefined`} example={readCode} exampleFile="actions.ts">

Every workspace action, bound to the store: each reads the current state, commits what it decides (layout, focus, address, announcement, toast) and returns the pane it opened or acted on, when there is one.

An action that would remove or replace a pane with unsaved work is held instead, and "Discard unsaved changes?" opens (`UiState.confirm`). A following detail with unsaved work keeps its object and says so. Every action is listed under <Ref to="Actions" page="/reference/core/types" />.

</Entry>

## The address and storage

<Entry name="createUrlSync" kind="function" from="@jali/core" signature={`createUrlSync(options?: UrlSyncOptions): UrlSync`} example={urlCode} exampleFile="url.ts">

Keeps the layout in the address. Pass it as the store's `url`; `boot` and `startUi` read from it too.

The layout goes in `?l=` (encoded with `layout.encode`), the maximised pane in `zoom`, the peek in `peek`. A curated page writes `page`, `item`, `tab` and one `open` per opened pane instead, and never its mode or layout: those are the reader's own. Every other search param is the host's and is kept as it is. Deliberate changes push a history entry; divider drags replace it 120 ms after the last move; maximise, peek and selection changes replace it at once. Moving focus alone writes nothing.

<Params>
<Param name="options" type="UrlSyncOptions" default="{}">

<ChildParams label="options">
<Param name="location" type="LocationPort" default="browserLocation()">The address: the browser's history, or a router adapter so the router stays its one owner.</Param>
<Param name="storage" type="StoragePort" default={`browserStorage("jali")`}>Where a link that couldn't be read is kept (`broken-layout`), and, with `sizes: "local"`, the person's dragged sizes.</Param>
<Param name="prefix" type="string" default={`""`}>Prefix for the workspace's search params when two workspaces share an address: `"b."` writes `b.l`, `b.zoom`, `b.peek`. It also prefixes the stored sizes key.</Param>
<Param name="sizes" type={`"link" | "local"`} default={`"local"`}>

What a layout link carries about sizes.

<Values>
<Value name="local">The layout as designed. Sizes the person dragged stay on this device, kept for up to 12 layouts by their structure, so their own reloads keep them and a colleague opens the link at the designed proportions.</Value>
<Value name="link">Everything: the link reopens exactly as it was.</Value>
</Values>

</Param>
</ChildParams>

</Param>
</Params>

<Returns type="UrlSync">A `UrlWriter` that can also `read(kinds)`, `keepBroken(code)`, `onPop(fn)` and give `href()`. See <Ref to="UrlSync" page="/reference/core/types" />.</Returns>

</Entry>

<Entry name="DEFAULT_KEYMAP" kind="constant" from="@jali/core" signature={`const DEFAULT_KEYMAP: { readonly "palette.toggle": readonly ["Mod+K"]; … }`} example={keymapCode} exampleFile="keymap.ts" exampleHighlight="12">

The default bindings: command id to one or more binding strings. `Mod` is ⌘ on a Mac and Ctrl elsewhere. Each id and its keys, printed for both platforms, are on the [Commands](/reference/commands) page.

The defaults keep to three rules:

- single character keys belong to the focused content;
- no keys the browser keeps for itself (⌘W, ⌘T, Ctrl+Tab and the like), no Ctrl+Alt, and no ⌘ or Ctrl with a digit;
- one prefix, ⌘K or Ctrl+K, which opens the palette and starts a two-step chord whose second step keeps Mod held.

</Entry>

<Entry name="PALETTE_ID" kind="constant" from="@jali/core" signature={`const PALETTE_ID = "palette.toggle"`} compact>

The keymap's id for opening and closing the command palette. It is a key binding, not a command: the palette does not list itself, and `commandsOf` does not include it. Rebind it like any command: `keymap: { [PALETTE_ID]: "F1" }`.

</Entry>

<Entry name="createKeymap" kind="function" from="@jali/core" signature={`createKeymap(overrides?: KeymapOverrides, opts?: KeymapOptions): Keymap`} example={keymapCode} exampleFile="keymap.ts">

Resolves the defaults and a host's changes into one keymap. A store makes its own from `deps.keymap`; call this for a keymap outside a store, or in a test.

A binding is refused (and reported to `onInvalid`) when it can't be parsed, is a single character key with no Mod, Ctrl or Alt (WCAG 2.1.4: those belong to the content), or has more than two steps. A command whose bindings are all refused is unbound.

<Params>
<Param name="overrides" type="KeymapOverrides" default="{}">Command id to a binding string, several, or `null` to unbind. Ids not listed keep their defaults; any other id (a registry command without a default, or your own) can be bound too.</Param>
<Param name="opts" type="KeymapOptions" default="{}">

<ChildParams label="options">
<Param name="platform" type={`"mac" | "other"`} default="detectPlatform()">The platform keys are matched and printed for. Pass it in tests and on the server.</Param>
<Param name="onInvalid" type="(id: string, binding: KeyString, reason: string) => void" default="console.warn">Called for each refused binding.</Param>
</ChildParams>

</Param>
</Params>

<Returns type="Keymap">`platform`; `entries` (every bound id and its sequences, in order); `sequences(id)`; `label(id)` (the first binding, formatted, or `""`); and `find` and `isPrefix`, which the keyboard layer uses to match a keydown.</Returns>

</Entry>

<Entry name="installKeyboard" kind="function" from="@jali/core" signature={`installKeyboard(store: UiStore, scope?: KeyboardScope): () => void`} example={keyboardCode} exampleFile="keyboard.ts">

Listens for the workspace's keys. `startUi` calls it with no scope; call it yourself for a workspace that should take only keys from inside its own element.

Keys go in this order. First, while active, the second step of a chord the person started and resize mode's arrows, Enter and Esc. Then the focused content: a key it claims with `preventDefault()` is left alone, and content marked `data-pane-keys="content"` keeps every key except F6 and Shift+F6. Then the keymap, then Esc (closes the peek, then leaves maximise). While the palette, Settings or the chooser is open, only the palette chord is taken. A bound command whose check refuses still takes the key, and announces the reason if it has one.

<Params>
<Param name="store" type="UiStore" required />
<Param name="scope" type="KeyboardScope" default="{}">

<ChildParams label="scope">
<Param name="target" type="Window" default="window">Where the listeners go.</Param>
<Param name="root" type="() => Element | null">The workspace's root element. Given, the workspace takes keys from inside it, and keys with nothing focused while it was the last place focus or a pointer went. Omitted, it takes every key on the page.</Param>
</ChildParams>

</Param>
</Params>

<Returns type="() => void">Removes the listeners.</Returns>

</Entry>

## Lists and their detail

<Entry name="activeItemPort" kind="function" from="@jali/core" signature={`activeItemPort(store: UiStore, pane: NodeId, mapping: ActiveItemMapping): ActiveItemPort`} example={activeCode} exampleFile="active-item.ts">

Lets a list inside a pane keep its current item through the workspace, so the pane's following detail follows it, Space shows it and an open peek steps with it. The shape matches Chakni's Quick Look port, so a Chakni collection plugs in with no dependency either way. In React, `useActiveItemPort`.
